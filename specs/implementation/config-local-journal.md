# Local configuration journal

`tickwire-config-journal` binds one WAL to a cluster, namespace, host, process, slot and locator generation. Creation syncs the scope header separately. Cluster, host and process use the configuration's lowercase names. Namespace and slot retain their UUID bytes. Each subsequent event occupies its own synced batch. [Journal crate](../../crates/tickwire-config-journal/src/lib.rs)

Every operation moves in order through `Prepared → Desired → RuntimeObserved → Effective`. Prepared records the old and new full version, target, control commit reference and expected instance. Each following event references the digest of its complete predecessor. Only one operation per scope can be unfinished. The next Prepared must use the last Effective as its exact base and a strictly higher target revision. Identical bytes for a completed step return the original sequence, digest and synced physical frontier. Different bytes conflict.

The schema 1 JSON envelope must round-trip byte for byte. A record can occupy up to 16 KiB. The journal permits 4,096 operations and 64 MiB of retained bodies, including its scope header. The physical recovery read limit also includes record framing and one incomplete batch. Projection objects are bounded at 4 MiB and materialized files at 8 MiB.

`Journal::recover_checked` verifies physical state and calls the business validator before truncating or syncing. An invalid scope, encoding, order, capacity or startup writer leaves the files untouched. `Recovery::observed_exec_epoch` includes a valid incomplete batch header so an old writer cannot truncate a newer writer's tail. That observed epoch grants no sync receipt. If an append's sync is uncertain, further appends stop and memory keeps the last confirmed state. Reopen recovers the actual complete prefix. A complete record whose acknowledgement was lost can then return its original receipt.

The recorded Linux tests exercised process death at every business step, dropped sync acknowledgements, invalid business records within valid physical batches, a newer writer's partial tail and real file receipts. The phase reported 13 business-journal, 22 config-fs and 22 physical-journal tests, including child helpers invoked by their parents. A journal receipt says that supplied evidence is durable.
