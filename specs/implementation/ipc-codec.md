# IPC Wire Codec, Hardware CRC32C, and Zero-Copy Market Record Views

`tickwire-ipc` defines the fixed-layout ABI 1.0 binary representations and deterministic validation rules for control-plane frames, shared-memory ring records, arena depth blocks, immutable resource envelopes, and normalized market snapshots. Generated little-endian encoders and decoders operate exclusively on stable, caller-owned byte slices without runtime JSON dependencies, heap allocation on hot record decode (`Record` uses stack-allocated variants and `ZeroCopyRecord` borrows 8-byte-aligned 512-byte market slots in place), or cryptographic signature verification.

The crate owns byte-level framing, field whitelists, hardware-accelerated Castagnoli CRC32C integrity primitives (`src/crc32c.rs`), `#[repr(C)]` zero-copy market views (`src/zerocopy.rs`), and structural payload invariants. Crate-level `[lints.rust] unsafe_code = "deny"` and `#[forbid(unsafe_code)]` on every general codec module keep all non-audited code safe, isolating `#![deny(unsafe_op_in_unsafe_fn)]` strictly to `crc32c` and `zerocopy`. `tickwire-ipc` intentionally does *not* map or synchronize live shared-memory pages: reading a producer slot or shared cursor page while another process mutates it is undefined behavior, so callers must first establish slot stability and lifetime bounds using the acquire/release `RecordBorrow` protocol in `tickwire-shm-sys` and `tickwire-shm`. File-descriptor permissions, `memfd` seals, `SCM_RIGHTS` transfer, `SO_PEERCRED` peer identity, arena reuse watermarks, and trading risk grants remain enforced by their respective subsystem owners.

## State Model and Bounds

All wire structures enforce ABI `1.0`, exact byte lengths, zeroed reserved padding, zeroed inactive union branches, and sequence/generation numbers strictly below `2^63` (`Error::SequenceExhausted` at `>= 2^63`). Integrity digests use Castagnoli CRC32C (reflected polynomial `0x82f63b78`, initial value and final XOR `0xffffffff`) when `--features crc32` is enabled (default OFF on intra-host memory/socket paths), and SHA-256 for immutable resource descriptors and snapshot bundles.

## Core Invariants

* **Capability negotiation precedes body interpretation**: `ControlFrame::decode_negotiated` checks negotiated session feature bits before parsing extension opcodes—specifically requiring feature bit 5 (`0x20`) for configuration-control opcodes `80..=84`—so unnegotiated peers cannot reach extension decoders.
* **Lease non-extension**: Configuration and execution grant validators check roles, host boot ID, configuration revision/hash, and durable receipt bindings against caller-supplied identities, and guarantee that a valid execution lease can never extend an already expired risk grant.
* **Typed reply correlation on control transitions**: `QUIESCE` (opcode `20`) success replies (`flags == 10`) must carry `evidence_kind == 1` and a zero `exit_evidence_id`. `SWITCH` (opcode `19`) replies require zero `snapshot_id` and `snapshot_seq`, pairing `flags == 10` with `switch_kind == 2` and `flags == 18` with `status == 32` and `switch_kind == 3`.
* **Audited hardware CRC32C and zero-copy bit-validity (`src/crc32c.rs`, `src/zerocopy.rs`)**: `crc32c` dispatches to `x86_64` SSE4.2 (`_mm_crc32_u64` over `as_chunks::<8>()` + `u64::from_le_bytes`, zero pointer casts) or `aarch64` CRC (`__crc32cd` / `__crc32cb`), falling back to a compile-time `const TABLES: [[u32; 256]; 8]` Slicing-by-8 implementation (`crc32c_slicing8`) with zero bit-by-bit loops, while `crc32c_masked` hashes masked header checksum ranges via zero-allocation `[0u8; 64]` chunks. Sealed `ZeroCopyRecord` implementations (`MarketRecord` and `MarketExactRecord`) contain exclusively primitive integers and fixed arrays (`u8`, `u16`, `u32`, `u64`, `i64`, `[T; N]`), enforced at compile time (`target_endian = "little"`, `size_of == 512`, `align_of == 8`, and `offset_of!` for every field), and validate pointer alignment plus all semantic/reserved-padding rules before casting `*const u8` to `&Self`.

## Operations and Failure Semantics

* **Replay control protocol (opcodes `41` / `42`)**: Replay request and reply frames carry fixed 256-byte `ReplayControlBody` payloads (`schema == 1`, `replay_kind` in `1..=10`, `object_bytes` in `1..=67,108,864`, and nonzero `instance_id`, `strategy_generation`, `logical_strategy_id`, `challenge`, `valid_until_mono_ns`, `object_digest`, `expected_cut_digest`, `operation_id`, and `operation_revision`). Kinds `1..=5` preserve legacy success-only reply rules; kinds `6..=7` arm and commit capture windows; kinds `8..=10` (`CaptureSeal`, `RebuildInstall`, `RebuildRollback`) additionally permit explicit refusal replies (`flags == 18`) with `status` in `1..=3` (`Unsupported`, `Busy`, `Invalid`), whereas acceptance uses `flags == 10`.
  * `CaptureSeal` (`8`) binds the capture ID, revision `1`, account prefix, contract digest, object digest, and challenge; both worker and host independently verify the live report session, PID, monotonic clock, shared cursor, and durable `WindowSeal`.
  * `RebuildInstall` (`9`) binds a schema-4 operation and revision, warm-input row count, and sealed window digest, which the SDK verifies alongside its retained input chain before installation.
  * `RebuildRollback` (`10`) sets expected sequence to zero, binds the original installation digest, and requires both a separate probe result and a complete recovery object set.
* **Checkpoint sealing and continuous observation**: Checkpoint seal requests (`96` bytes) and replies (`256` bytes) correlate via `validate_checkpoint_reply(request, reply, previous_ready_sequence)`, requiring `schema == 1`, nonzero 16-byte `challenge`, matching `instance_id`, `logical_strategy_id`, `strategy_generation`, `seal_mode`, and echoed `report_sequence`, plus `ready.ready_sequence > previous_ready_sequence`. In exact modes (`seal_mode` `0` or `1`), `ready.exec_report_sequence` must equal `request.report_sequence`. In `CHECKPOINT_OBSERVE_CURRENT` (`seal_mode = 2`), `request.report_sequence` acts as a floor (`ready.exec_report_sequence >= request.report_sequence`) while the reply echoes the requested floor and the embedded `READY` record reports the actual observed watermark. Authenticated callers must still verify session liveness, deadline, and retained account-prefix digests.

## Verification and References

```sh
python3 crates/tickwire-ipc/tools/generate.py wire
python3 crates/tickwire-ipc/tools/generate.py tests
cargo test --locked -p tickwire-ipc --all-targets
cargo test --locked -p tickwire-ipc --features crc32 --all-targets
cargo clippy --locked -p tickwire-ipc --all-targets -- -D warnings
```

The code generator embeds the SHA-256 digest of `ipc-wire-v1.json` directly into the generated Rust source so contract drift fails review and verification. Automated suites run 46 generated field-offset/size layout tests (backed by compile-time `offset_of!` assertions), 95 independent golden-vector tests (`ipc-vectors-v1.json`) that catch symmetric encoder/decoder bugs, differential HW-vs-Slicing-by-8 CRC32C tests across alignments `0..8` and lengths `0..=4,096`, and dedicated semantic suites covering both `crc32` feature modes, zero-copy alignment rejection, truncation, nonzero reserved bytes, arena class mismatches, replay refusals, and exact-value market records.
