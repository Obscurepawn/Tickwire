# 持久命令发送协调

接口见发送协调。`JournaledSender` 同时拥有业务日志、授权服务、交易所编码器和连接，外部不能绕过它取得可写连接。规范命令与日志请求逐项核对风险域、交易所、产品、环境、账户、意图、原执行代次、策略代次、配置版本、截止时间、恢复对象和摘要。序号、预算符号、算术溢出及提交模式也在提交前检查。

编码器在授权与 WAL 之前准备完整报文，失败不产生持久意图或输出。授权服务验证策略权限、风险预算并保存完整恢复依赖；日志核验返回的私有闭包凭据后同步意图。只有成功提交的命令进入连接发送槽。`max_intents` 限制内存中的意图数量，达到上限时拒绝新意图；本层不淘汰去重历史。

`poll` 先推进建连、握手与已有输出，再通过 `try_send` 尝试接纳明文。首次接纳前调用当前授权服务，检查新的时间、执行权和账户状态。传输层尚未接纳字节时，每次重试都重新检查；一旦接纳，继续发送同一缓冲区，不重建命令。连接、队列和字节进度都由同一个 `&mut self` 所有者访问。

`NoBytes` 先追加同步中止记录，再把状态改为 `Aborted`。日志同步失败、部分接纳后取消、断线或冲突意图均冻结协调器，并保留未中止意图为 `Unknown`。重复的相同意图返回当前状态，不再次排队；不同内容的相同意图冻结。`AwaitingResponse` 的完成点是本机 socket 接收完整报文，此时仍保留风险占用。

恢复首先验证物理与业务日志，再由授权服务验证每个完整闭包并加载原始规范命令。加载结果仍执行全部身份与摘要核验。没有持久中止的意图都恢复为 `Unknown`；持久中止保持 `Aborted`。恢复后的实例没有网络连接且保持冻结，旧命令不会自动重发。它可以在更大的 writer epoch 下恢复原始订单，订单自身的原代次保持不变。

## 组合边界

账户预算、策略权限和模式检查由 `Authorization` 的实现提供，本模块没有默认放行实现。当前集成测试使用明确的授权与对象存储 Mock，由恢复清单实现校验完整命令对象；资金账户 reducer 的组合另行实现。现有 `OrderRequest` 只表达单一标量预算，本模块不把它推断为完整的多资产风险批准。

业务 ACK、私有成交、费用和余额还需经过协议身份关联与持久化入账。读取网络数据不会自动确认订单或释放预留。当前 `RestEncoder` 连接 Binance REST 编码与真实 HTTP 输出；WSS 登录、请求关联和连接轮换在会话层扩展。

## 回归

失败日志保存七项编译成功后的行为失败，最初接口尚未实现发送与恢复。初次实现回归暴露两处测试装置问题：物理日志构造参数中的 stream/domain 顺序错误，以及 macOS 上接受 socket 继承了监听器的非阻塞状态。修正测试输入和服务端 socket 模式后，原八项生命周期测试通过。

后续回归逐项拒绝失效门禁，检查过期期限、冲突去重、新 writer 恢复、缺失命令对象与中止同步失败。真实 Binance REST 集成分别验证 Spot 和 USD-M 的签名、完整请求、WAL 与首次门禁顺序。服务端从实际 TLS 收到的报文独立验签。
