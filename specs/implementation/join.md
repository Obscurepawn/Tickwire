# Market-Topic JOIN Protocol and Stateless In-Memory Idempotency

`tickwire-join` (`JoinOwner<M>` and `JoinConsumer<B>`), the stateless publisher control server in `tickwire-md` (`Server` + `BoundedRequestStore`), and the nonblocking client state machine in `tickwire-market-source` (`PendingJoin`) coordinate race-free subscription onboarding and detachment on a live shared-memory market topic. Because `tickwire-md` continues appending ring records while a subscriber connects, maps memory, and builds its in-process `MarketReplica`, `JoinOwner` reserves a ring reclamation gate at cut `S` *before* building a sealed baseline snapshot at `S`, offers read-only descriptors for both the live bank (`0x17`) and immutable snapshot (`0x0f`), binds the subscriber's single-writer cursor (`0x17`), and withholds `Stage::Active` until the subscriber has loaded the baseline at `S` and caught up its `applied` watermark to the publisher's live `published` sequence. Binance depth topics and Bybit/OKX BBO-only topics run this identical protocol; each instrument's `required_states` mask determines what state categories the baseline and replica must satisfy.

`JoinOwner<M>` serializes membership transitions under a single writer while up to `M` subscribers advance their own mapped cursors independently. Inside `tickwire-md`, control-plane request idempotency is maintained exclusively in a bounded pure in-memory `BoundedRequestStore` with zero disk state. Forcible reclamation of dead consumer processes and execution risk authorization remain separate authorities outside `tickwire-join`.

## State Model and Bounds

`JoinOwner<M>` retains up to `M` (`<= 32`) registration entries—including `Failed`, `Expired`, and `Detached` slots—keyed by `SubscriptionKey { bank, instance, generation, cursor }`. In `tickwire-md`, `BoundedRequestStore` implements `tickwire_control::RequestStore` in memory (`max_join_requests`, defaulting to `4,096`), indexing requests by `RequestKey { domain, issuer_instance, issuer_generation, opcode, request_id }` and deterministically evicting the oldest completed entry in FIFO completion order whenever capacity is reached while preserving all `Pending` entries. On the client side, `PendingJoin` drives a 16-phase nonblocking state machine (`Connect` through `Complete`) using `JoinConsumer<4>`.

| Owner Operation / Client Limit | Protocol Evidence and State Transition |
| --- | --- |
| `BoundedRequestStore` (stateless `tickwire-md`) | Pure in-memory bounded table (`1..=65,536` entries, default `4,096`, bounded `max_pending`). Duplicate requests with identical `(session_id, body_hash)` return `AdmitOutcome::Completed` or `AdmitOutcome::InProgress`; mismatched digests or session IDs fail with `Error::Conflict`. Completed entries retire in deterministic FIFO order at capacity; `Pending` entries are never evicted. |
| `prepare` (opcode `16` via supervisor `role == 1`) | Admits via `Session::admit` (`BoundedRequestStore` deduplication), verifies subscriber `role` (`3` or `4`), `join_flags == 3`, instrument-set hash/version, and `now < readiness_deadline <= supervisor.deadline()`, calls `Publisher::join(sub)` to lock cut `S = first - 1` (`Stage::Reserved`), builds and `0x0f`-seals the `ImmutableResource` snapshot, records `ExecutionTicket::complete`, and enters `Stage::Prepared`. Any build/seal failure moves the entry to `Stage::Failed` *while keeping the ring gate at `S` installed*. |
| `deliver` (opcode `3`, `RESOURCE_OFFER`) | Verifies subscriber session and deadline, duplicates and sends read-only `SCM_RIGHTS` descriptors for the bank (`kind 1`, mask `0x17`, profile `1`) and snapshot (`kind 2`, mask `0x0f`, profile `2`), transitioning to `Stage::Delivered` (or `Stage::Failed` on transport error, retaining the gate). |
| `receive_cursor` (opcode `3` from subscriber) | Accepts exactly once in `Prepared` or `Delivered`; validates `offer_id(join, 3)`, mask `0x17`, and exact 8,192-byte cursor `ResourceDescriptor`, then maps and binds the cursor via `Publisher::register_pending_cursor` (`cursor_registered = true`) without premature activation. |
| `read_ready` (opcode `5`, `RESOURCE_ACK`) | Independently validates bank (`kind 1`, `0x17`) and snapshot (`kind 2`, `0x0f`) acknowledgements against `offer_id`, `descriptor_hash`, `resource_bytes`, `access == 1`, `ack_kind == 2`, `subscription_generation`, and `membership_version`, setting `bank_ready` / `snapshot_ready` only on success. |
| `join_ready` (opcode `17`) & `catchup_target` | Requires `Delivered`, `bank_ready`, `snapshot_ready`, `cursor_registered`, `ValidatedTopic::check_readiness(now)`, monotonic non-regressing cursor watermarks, and `actual.applied >= publisher.published()` sampled within the same exclusive call. If `applied < published`, returns `Cursor` error while `catchup_target` exposes `Some(published)`. Once caught up, calls `Publisher::activate_join`, enters `Stage::Active`, and caches `activated: Some(Watermarks)` so authenticated retries return the original activation watermarks. |
| `expire(now)` | Moves any non-`Active` / non-`Quiescing` / non-`Detached` registration past `readiness_deadline_mono_ns`—or all such pending registrations on clock regression (`now < last_now`)—to `Stage::Expired` while keeping their ring gates intact. |
| `quiesce` / `quiesced` (opcode `20`) & `all_detached` | `quiesce` records the outbound `QuiesceBody` and enters `Stage::Quiescing` (idempotent on retry). `quiesced` validates `flags == 10`, `evidence_kind == 1`, zero `exit_evidence_id`, and calls `Publisher::detach_registered` (requiring mapped cursor `lifecycle == 5`, zero outstanding borrows, and `quiesced_seq == read == released`), entering `Stage::Detached` and dropping the snapshot `ImmutableResource`. `all_detached()` returns `true` only when `entries` is empty or *every* historical entry is `Stage::Detached`—socket EOF or timeout never proves detachment. |
| `PendingJoin` bounds | `startup_timeout_ms` in `1..=60,000` ms; `maximum_levels` in `1..=10,000`; `poll(now, budget)` rejects `budget == 0` and executes at most `min(budget, 64)` steps or ring records; retained catch-up buffer capped at `bank.capacity` records and `64 MiB`; cold baseline validation bounded at `64 MiB` and `4,096` instruments. |

## Core Invariants

* **Gate-before-snapshot ordering**: Installing the pending subscriber gate on `Publisher` *before* invoking the snapshot builder guarantees that even if concurrent market events arrive or the snapshot build fails partway through, no slot `>= S + 1` can be overwritten without explicit cursor detachment, and retrying the `JOIN` request through `BoundedRequestStore` can never construct a second cut.
* **Pure in-memory bounded deduplication**: `BoundedRequestStore` performs zero file I/O, zero `fsync`, and zero heap growth beyond its configured entry bound. Retrying a completed `JOIN`, `QUIESCE`, or `SWITCH` frame while its key remains within the bounded table returns the original `CompletedRequest` outcome without re-executing `JoinOwner` mutations, and `Pending` keys cannot be displaced by completed traffic.
* **Split `WELCOME` receipt and clock re-sampling**: In `PendingJoin`, receiving `WELCOME` (`Phase::Welcome`) rejects any attached FDs, buffers the bounded frame, transitions to `Phase::ValidateWelcome`, and yields from `poll` (`runnable = true`) *before* calling `ClientHandshake::finish`. Because the publisher may have minted `WELCOME.lease_deadline_mono_ns = server_now + lease_duration_ns` slightly after the client's pre-`recv` timestamp `t0`, yielding forces the caller to pass a fresh `CLOCK_MONOTONIC` sample `t1 >= server_now` on the next `poll`, preventing false `deadline - t0 > lease_duration_ns` rejections while still catching genuine clock regressions (`t1 < t0`) and startup timeouts (`t1 >= expires`).
* **Monotonic catch-up retention before cursor advance**: After attaching `JoinConsumer<4>` and loading the sealed baseline into `MarketReplica`, `PendingJoin::drain_one` borrows each ring record starting at `J = S + 1`, retains `{ record, payload, instrument, applied_mono_ns }` inside the bounded catch-up vector, applies the update to `MarketReplica`, drops `RecordBorrow` (advancing `released`), and calls `consumer.apply(sequence)` (advancing `applied`). The catch-up `target` sequence never retreats; if the publisher advances while `JOIN_READY` is in flight, the client drains the newly published delta and resends `JOIN_READY`.

## Operations and Failure Semantics

* **Nonblocking backpressure and single-take handoff**: `PendingJoin` uses `PendingConnection` and `try_send`/`try_recv`. On `WouldBlock` or `EINTR`, `State` preserves the current `Phase` and any unsent `Outgoing { bytes, fd }` buffer so the next `poll` resumes cleanly without duplicating protocol frames. Any fatal protocol, validation, or deadline error automatically calls `cancel()`, dropping local mappings and sockets without ever fabricating a `QUIESCED` proof. `take_client()` transfers the live `Client` (together with its retained `baseline_bytes` and `catchup` prefix) at most once, strictly after `Phase::Complete` confirms authenticated `Active` status and drains through the activation watermark. `Client::connect` drives the identical `PendingJoin` state machine for blocking callers.
