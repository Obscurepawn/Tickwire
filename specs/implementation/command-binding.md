# Binding a persisted intent to its command

A scalar `OrderRequest` carries a mandatory non-zero, 32-byte `command_digest`. The kernel includes it in request equality, the durable record and commit identity. A zero digest fails before reservation or recovery can introduce an order. The order state stays fixed in size. The complete canonical command is stored as a separate immutable dependency. [Execution types](../../crates/tickwire-execution/src/lib.rs) · [Canonical command](venue.md)

Business codec schema 2 places the digest at key 14 of `PreparedIntent`. Business digests, logical payload hashes, chain genesis and chain nodes use versioned domains. The maximum encoded record is 236 bytes. The business bootstrap identifies the codec version. The current reader rejects schema 1 because that representation cannot bind the missing order parameters. [Business codec](../../crates/tickwire-journal-codec/src/lib.rs) · [Current golden vectors](../../crates/tickwire-journal-codec/tests/golden-v2.json)

A recovery manifest may include one complete command object at dependency kind 13. Publication and verification check the object's actual bytes, length and SHA-256 and confirm durable storage. The private `VerifiedClosure` records its digest. First commit, an idempotent commit return and runtime recovery each require it to match the prepared intent's command digest. A closure with a valid business digest but no matching command object cannot authorize commit. A changed command under an existing intent is a conflict. [Recovery closure](../../crates/tickwire-recovery/src/lib.rs) · [Business journal](../../crates/tickwire-business-journal/src/lib.rs)

The binding proves byte identity and persistence. The venue validator interprets product fields. The gateway still checks routing, environment, asset units, authorization and the actual encoded output. Calling the scalar `Exchange::submit` interface does not establish that a network writer accepted any bytes. File recovery, missing or duplicated dependencies, mismatched capabilities, changed same-intent content and durable abort ordering have separate tests. [Runtime tests](../../crates/tickwire-business-journal/tests/runtime.rs) · [Closure tests](../../crates/tickwire-recovery/tests/closure.rs)

The bounded L1 model covers command digest, dependency identity, conflicts, WAL write and sync failures, and crashes. Its send action observes an exchange-interface call, not a decoded protocol request or the TLS writer's first byte.
