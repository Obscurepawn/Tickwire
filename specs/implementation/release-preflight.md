# Preflight for a strategy release

`tickwire-release` verifies the three canonical objects, the complete operation and member, actual file lengths and digests, input order, target capabilities and rollback capabilities. The registered factory executes restore or migration. The built-in FixedDemo preserves its consumed action, and any new intent binds to the target instance and the same economic action key. Unsupported restore and rebuild methods return `Unsupported`.

The host accepts RestoreApplied from the child authenticated by its registry. Check PID/UID/GID, executable digest, actual bootstrap, pinned source and synchronized output. A separate rollback probe connects only to the authenticated control socket and runs the rollback factory using the target output. The host waits for successful exit, then persists both receipts and Completion. The worker verifies the confirmation and closure before callbacks. Schema 2 HandoverSeal refers to Completion.

On Linux, open `/proc/self/exe` and hash the actual image through that same descriptor within the binary budget. Both sealed memfd and disk ELF follow this rule. Restore and rollback also need the readable, independently pinned `Role::Binary` artifact at its verified length, identity and digest. A renamed launch path leaves the executing inode unchanged.

The loader verifies the actual HostConfig/Bootstrap, RecoveryTemplate and every file the template references. A retained source comes from the authenticated old host and a real report cursor. A host retains up to 64 source metadata records. Prepare and Commit check the operation schema, completion objects, account product/position mode and supported open-order types. After quiescing, issue a fresh checkpoint challenge. Its business bytes must match the fixed source. Verify the current READY account cut separately from the fixed migration root.

Local recovery and replica recovery use the same closure verifier for Completion, both receipts, target and rollback outputs, and full account callback history. Historical v1 records remain readable. New Prepare requires preflight. Limit a closure to 256 distinct objects, 16 source levels and the recovery byte budget. See [strategy replay](strategy-replay.md) for schema 3 and [declared rebuild](strategy-rebuild.md) for schema 4.
