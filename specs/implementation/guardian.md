# Emergency account access

`tickwire-guardian` is an optional independent owner for queries and cancellations on a fenced Binance account. Start it with `cargo run -p tickwire-guardian -- --config /absolute/guardian.json`. The strict deployment JSON identifies the guardian and expected old execution owner, products, instruments, audit location, trusted roots and endpoints, calibrated clock, quota configuration, independent credentials, canonical command files and signed authorization. Fencing and emergency grants use distinct Ed25519 keys. The credentials file grants no group or other access.

The operator supplies a verified external isolation certificate. The guardian verifies that certificate against its trusted key. A local allowlist accepts queries, order cancellations, list cancellations and algo cancellations. The exchange account's key permissions are set at the venue. Before opening an exchange or time connection, `start_quota_run` persists the quota consumer identity. A restart cannot reuse the same allocation. The CLI combines a real file store, TLS, time client and charging endpoint with an explicit `MockQuotaStore` for external allocation control.

Persist the canonical command, signed grant, request digest, connection epoch and local clock domain before the first TLS application write. Write the audit in chunks and commit a length and SHA-256. An incomplete tail stays unpublished. Zero accepted application bytes produce `NoBytes`. A partial send or recovery of a request without a complete result produces `Unknown`. A complete valid successful HTTP/JSON response produces `Response`. Native rejection, missing order, rate limit and authentication errors retain their original response and classification.

An existing command key returns the persisted result or Unknown on recovery. The account owner reconciles cash and grants separately. Audit replication is outside this profile, so `audit_degraded` is true. See [guardian](../../crates/tickwire-guardian/) and [fencing](../../crates/tickwire-fencing/) for the software and proof boundaries.
