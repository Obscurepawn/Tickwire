# Strategy SHM Market Subscription, DOP Logon, and Inline Execution I/O

`tickwire-strategy-sdk` drives stateless strategy worker processes in the 3-process shared-memory topology (`tickwire-md` + strategy workers + unified ORS execution process). Each strategy worker connects directly to `tickwire-md` shared-memory broadcast rings at an independent reader cursor, authenticates with the ORS execution process over the Direct Order Entry (`DOP`) control handshake (`DopLogin` -> `DopEcho` + `OrsSessions`), encodes outbound orders, cancels, modifies, cancel-alls, and RFQ quotes directly into 1,024-byte `IntentRecord` shared-memory slots, and decodes inbound 512-byte `ReportRecord` shared-memory replies in place with zero local persistence.

Economic instrument catalog digests (`instrument-catalog.md`), per-account balance/position holds, and venue wire signing remain enforced by their owning boundaries (`tickwire-instrument-catalog` and the ORS execution process).

## State Model, DOP Session, and Bounds

At cold boot or restart, a worker validates its static bootstrap configuration and optional CPU isolation (`worker_cpu: Option<u32>` and `housekeeping_cpus: Option<CpuSet>`, verified via `tickwire_control_sys::validate_cpu_isolation` so `worker_cpu ∩ housekeeping_cpus == ∅`). Background housekeeping (`"strategy-cold"`) spawns onto `housekeeping_cpus` via `tickwire_control_sys::spawn_pinned_thread` (`worker::spawn_housekeeping`) before the hot strategy loop pins itself to `worker_cpu` via `tickwire_control_sys::pin_current_thread` (`worker::pin_worker_thread`). Inside the hot loop (`WorkerDriver::step` and `worker::run_qualified`), `poll_quiesce_market` and `poll_control_quiesce` service authenticated `QUIESCE` frames so the worker cleanly detaches its mapped SHM cursors and sends `DopLogout` on shutdown.

## Core Invariants

* **Zero-copy market and report consumption (`market.rs`, `reports.rs`)**: Live market ring drains borrow `&MarketRecord` / `&MarketExactRecord` directly in mapped memory while `RecordBorrow` holds the release watermark (`0` heap allocations on normal updates). Similarly, `ReportReceiver` validates and borrows `&ReportRecord` in place via `ReportRecord::from_aligned_bytes`, copying optional oversize payloads only from validated in-memory SHM Arena blocks (`validate_report_arena_payload`). By default (`not(feature = "crc32")`), `IntentWriter` and `ReportWriter` clear checksum flag `0x08` and write `record_crc32c = 0`; enabling `--features crc32` activates Castagnoli CRC32C generation and verification.
* **Stateless sequence floor adoption on DOP reconnect (`dop.rs`, `outbound.rs`)**: Because strategy workers hold zero local state files across restarts, the ORS execution process reconstructs open orders from Exchange REST snapshots + `tw1...` `SelfDescribingClientId` attribution and returns `next_source_order_seqnum` in `DopEcho`. Adopting `next_order_seqnum = max(1, echo.next_source_order_seqnum)` while resetting transport `msg_seqnum` to `1` prevents `order_seqnum` and `tw1...` collisions without reading prior disk logs.
* **Strict separation of `Execution`, `FeeAmendment`, and `Projected` fills (`reports.rs`, `microstructure.rs`)**: `ReportRecord` message `773` (`Fill`) enforces `!(amendment == 1 && projected == 1)` on the wire and decodes into three explicit `FillKind` variants:
  * `FillKind::Execution` (`amendment == false && projected == false`): authoritative per-trade execution (`last_qty_lots`, `last_price_ticks`, `venue_trade_id`, optional fee).
  * `FillKind::FeeAmendment` (`amendment == true`): post-trade commission/rebate update (`fee_units`, `fee_asset_id`, `asset_exponent`) that **never** changes `confirmed_filled` or `projected_filled` quantity watermarks.
  * `FillKind::Projected` (`projected == true`): early cumulative order-status fill projection (`cum_qty_lots`) advancing `projected_filled` ahead of individual trade reports without double-counting when the matching `Execution` fill arrives.
* **Monotonic pure-`Fixed` `FillWatermarkTracker` (`microstructure.rs`)**: Built under `#![forbid(unsafe_code)]` with exact integer/256-bit `round_half_even` fixed-point math (`0` floating-point instructions):
  * `confirmed_filled(order)` tracks deduplicated settled `Execution` fills across a bounded per-order `trade_id` window.
  * `projected_filled(order)` maintains `max(confirmed_filled, cumulative_observed)`; stale cumulative observations (`cum_qty <= watermark`) are ignored (`Ok(None)`).
  * Settled `Execution` fills advance inventory skew only by `unprojected_delta = max(watermark, confirmed_after) - watermark`, preserving $\sum \Delta_{\text{skew}} = \text{projected\_filled}$ across arbitrary status/trade reorderings, while `FeeAmendment` reports return `FeeAmendmentOutcome` without altering fill quantities.
* **In-place `Modify` and `CancelReplace` validation (`outbound.rs`)**: `ModifyRequest` validates strictly positive integer/fixed-point `price` and `quantity`, tick/step alignment, and target order identity (`orig_order_seqnum` or `orig_client_id` / `venue_order_id`) before encoding `IntentRecord` (`message_type = 517`, `command_kind = 5`), optionally minting a replacement `tw1...` `SelfDescribingClientId` (`REPLACEMENT_ORDER_LEG`).

cargo test --locked -p tickwire-strategy-sdk -p tickwire-strategy-example --all-targets

SDK and example test suites exercise authenticated `DopLogin`/`DopEcho`/`OrsSessions`/`DopHeartBeat`/`DopLogout` sessions over `SOCK_SEQPACKET`, inline 1,024-byte `IntentRecord` encoding across `NewOrder`/`Cancel`/`CancelReplace`/`AmendKeepPriority`/`Modify`/`CancelAll`/RFQ intents (`tick_mono_ns`, `account_ref`, `RPI`), oversize in-memory SHM Arena slice validation, zero-copy 512-byte `ReportRecord` decoding across all lifecycle/rate-limit/shutdown messages, `FillWatermarkTracker` conservation across `Execution`/`Projected`/`FeeAmendment` interleavings, and `worker_cpu` vs. `housekeeping_cpus` affinity isolation.
