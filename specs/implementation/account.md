# Stateless Multi-Asset Account Ledger and Zero-Allocation ORS `OrderManager`

`tickwire-account` (`#![forbid(unsafe_code)]`) implements both the deterministic multi-wallet / unified-trading-account (`UTA`) financial state machine (`Account`) and the zero-allocation, fine-grained spinlocked ORS execution state core (`OrderManager<const CHECK_STP: bool = true>`, `OrsOrder`, `LockedOrder`, `OrsStpBook` / `LockedSymbolBook`, `FillRecordPool`, `DopState`, `UtaWalletLedger`, and `OrsQueryDesk`).

Cold startup and process restart recover exclusively from authenticated Exchange REST snapshots (`Account + OpenOrders`) paired with domain-authenticated 32-character `[0-9a-z]` `SelfDescribingClientId` (`tw1...`) tokens, reconstructing open-order holds, self-trade prevention (`STP`) book entries, strategy attribution, and per-strategy sequence watermarks with zero local disk state.

## State Model and Bounds

Every monetary and quantity value uses exact integer ticks, integer lots, or `Fixed { atoms, scale }` (`i128` atoms, decimal scale `0..=38`) paired with an explicit `AssetKey { wallet_id, asset_id }` (convertible losslessly from `tickwire_venue::AssetKey`) across `Spot`, `UsdM`, `CoinM`, `Option`, `LinearPerpetual`, `InversePerpetual`, `LinearFuture`, and `InverseFuture` wallets. Floating-point arithmetic is forbidden across all admission, STP, projection, and settlement paths.

## Core Invariants

* **Immediate slot retirement and `StpBook` unlinking**: Neither `OrderManager` nor `Account::Order::is_retirable` waits for fee reconciliation before retiring a terminal order. Full fill, cancel to zero remainder, or venue reject transitions the slot to `Retired` (`retired_mono_ns = Some(now)`) and unlinks all resting/pending prices from `StpBook` in the same call. Post-terminal fee patches and maker rebates resolve against `FillRecordPool` (or `Account` trade facts) and emit `Fill { amendment: true }` updating wallet cashflow only.
* **Exact `dry_run` isolation**: `OrderManager` reads `dry_run` at exactly two boundaries: (1) slot selection, routing `dry_run` intents to the strategy's dedicated scratch slot so live ring slots and `next_order_seqnum` watermarks are untouched, and (2) transport send suppression, returning `should_send_to_venue: false` after executing full validation, sequence, RMS/ledger, and lock-free `StpBook` checks.
* **Microstructure exactness (`FrontAck`, single `Ack`, `pending_cxl`, `cancel-before-ack`, `ProjectedFill`)**:
  1. Optional `FrontAck` (`VenueEvent` / `v::FrontAck`) emits at most once while `PendingNew`.
  2. Whichever channel arrives first (order socket reply or private stream) emits the single `Ack` and transitions `PendingNew -> Open`; a second ack on an already-`Open` order is a no-op unless venue-modified price/qty moved (`Modified`).
  3. Each strategy/admin cancel increments saturating `pending_cxl`; venue terminal cancels preserve explicit causes (`MKT_IOC_CANCELED`, `MKT_REJECT_POST_ONLY`, `MKT_REDUCE_ONLY_CANCELED`, `MKT_CANCELED_SELFTRADE`) and classify generic cancels as `NO_REASON` when `pending_cxl > 0` versus `MKT_CANCELED` when `pending_cxl == 0`.
  4. When `cancel_before_ack` (`CANCEL_ON_SAME_BEFORE_ACK`) is enabled, cancel requests against `PendingNew` orders increment `pending_cxl` and dispatch immediately on the same ordered connection; otherwise they latch `cancel_after_ack` to dispatch upon `Ack`.
  5. `ProjectedFill` (`on_cum_qty`) advances `projected_filled_lots` ahead of delayed trade frames so terminal cancel releases `cxl_qty = max(0, effective_qty - projected_filled_qty)` without double-deducting holds when the real `Fill` arrives.
* **Strict lock hierarchy**: Callers never overlap `OrderSlot` and venue `Connection` spinlocks. `LockedSymbolBook` can only be acquired while holding the single caller `LockedOrder`, and administrative multi-order scans (`find_orders` / `set_strat_enabled`) lock, inspect, and release one order slot at a time in ascending slot index order.

## Stateless Cold Exchange Bootstrap

Both `Account::from_live_exchange` and `OrderManager::bootstrap_from_exchange` initialize exclusively from authenticated Exchange REST `Account + OpenOrders` snapshots:

1. Settled balances and net derivative positions enter shared bucket `0` across all configured `AssetKey { wallet_id, asset_id }` entries without historical trade pagination.
2. Each open order carrying a valid `tw1...` `SelfDescribingClientId` restores `(strat_id, epoch, order_seqnum)`, populates its deterministic `slots_per_strat` slot as `Live` (`Open`, `ack_emitted = true`), records pre-snapshot `filled` watermark so post-restart fills book only incremental deltas, links remaining resting quantity into `StpBook`, and advances `DopState`'s per-strategy `next_order_seqnum` floor above all live orders.
3. Spot/UTA baseline locks normalize `remote_free + explained_locked` while isolating unexplained external locks into `nontrade_locked`.
