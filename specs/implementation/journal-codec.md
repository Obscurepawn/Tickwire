# Scalar business journal codec

Schema 2 encodes `PreparedIntent`, `Fill`, `Fee`, `Terminal` and `AbortedBeforeSend` in at most **236 bytes** per record. The old schema-1 sample had a 201-byte maximum. It is now a rejection fixture. Each canonical record separates its continuous `journal_seq` and current `writer_exec_epoch` from the originating order's `intent_seq` and `intent_exec_epoch`. A later writer can record a fill for an earlier order without changing the fill's economic identity. ## Encoding and chain

The wire format uses explicit CBOR fields, definite lengths, fixed enum tags and shortest-form integers in network byte order. It does not depend on the Rust memory layout. All `i128` values round-trip, including `i128::MIN`. Negative magnitude is computed as the bitwise complement of the signed value to avoid overflow on negation. Bignums use tags 2/3 and a 9–16-byte magnitude with no leading zero, bounded by the signed range. Business legality remains the reducer's responsibility. The reader checks every required key in order and allocates no buffer from an untrusted length. [CBOR implementation](../../crates/tickwire-journal-codec/src/cbor.rs)

`business_digest` binds the risk domain, original order epoch, event kind and all economic fields, including the original command digest for a prepared intent. Changing the deadline, reserved capital or configuration changes the digest. Moving an identical fact to another journal position or writer leaves that digest unchanged. `logical_payload_hash` additionally binds the current writer epoch. A logical chain node then binds the preceding hash, domain, journal epoch, position, event kind and logical payload hash. Physical segment IDs, frame bytes, batch IDs and LSNs belong to the physical WAL. [Logical chain](../../crates/tickwire-journal-codec/src/chain.rs)

The chain starts at the stream genesis. Domain or epoch mismatch, a gap, repeated or exhausted sequence, regressing writer epoch or mismatched expected hash rejects the transition and preserves the previous chain. An economic duplicate may occupy a new valid journal position. The execution reducer still deduplicates the underlying fill or fee. A valid chain alone proves neither a disk sync nor authority to trade.

## Verification

Independent fixed vectors cover encoded records, business and logical hashes, chain genesis and integer boundaries. The checked-in schema-1 fixture exercises version rejection. Truncation, trailing bytes, unknown or reordered keys, duplicate keys, wrong types, non-minimal encodings, overlong input and single-byte mutations exercise canonicality. For an accepted mutation, re-encoding must reproduce its bytes exactly. The runtime separately matches each business envelope to the physical WAL and verifies recovery dependencies and send eligibility.
