# Shared-Memory Broadcast Ring, Inline Intent/Report Slots, Arena Reclamation, and Cursor Gating

`tickwire-shm` implements the single-producer, multi-consumer shared-memory broadcast protocol (`Producer`/`Reader` pure state machines and `Publisher`/`Subscriber` mapped SDK) over single-writer Linux `memfd` mappings. One `Publisher<M>` owns a fixed-generation bank (resource kinds `1..=3`: market `512` B, intent `1,024` B, or report `512` B) and coordinates up to `M <= 32` independent `Subscriber<B>` consumers, each exporting its own 8,192-byte single-writer cursor mapping (`resource_kind = 4`). Strategy intents (`IntentRecord`, `1,024`-byte aligned slots) and ORS execution reports (`ReportRecord`, `512`-byte aligned slots) travel completely inline inside shared memory—with optional size-segregated in-memory SHM `Arena` blocks (`(arena_offset, arena_len)`, `payload_kind = 2`) for oversize payloads and zero `FileBlobStore` or disk I/O. Rather than letting slow consumers suffer silent ring overwrites and torn reads, the publisher gates slot and arena reclamation on the minimum `released` watermark across all registered consumers—including pending `JOIN` registrations from the instant their baseline cut is reserved.

`tickwire-shm` owns batch slot reservation, optional size-segregated arena allocation, non-escaping `RecordBorrow` lifetime guards, out-of-order release/application prefix tracking, and cursor-verified detachment/freeze transitions. `tickwire-shm-sys` enforces OS `memfd` seals and aligned 64-bit acquire/release operations, `tickwire-ipc` validates inline record framing, zero-copy views (`MarketRecord`, `MarketExactRecord`, `IntentRecord`, `ReportRecord`), and arena payload headers, and `tickwire-join` / `tickwire-control` authenticate peer processes, transfer file descriptors (or DOP TX/RX ring descriptors), and link successor ring epochs.

## State Model and Bounds

A mapped bank begins with an immutable 4,096-byte `ResourceHeader` (`offset 0`), followed by a 4,096-byte producer atomic page (`offset 4096`), contiguous fixed-width ring slots starting at `SLOTS = 8192`, and—when external arena classes are configured (`ArenaClass` `1..=4`)—up to four contiguous size-classed shared-memory arenas immediately after the slot array. Each subscriber cursor is an independent 8,192-byte mapping with its `ResourceHeader` at `offset 0` and 128-byte-isolated `u64` atomic watermarks in page 1 (`offset 4096`).

| Region or Parameter | Layout / Enforced Bound |
| --- | --- |
| Ring capacity & batch size | Power-of-two `capacity` in `64..=1,048,576` (`2^6..=2^20`) slots; `1..=64` records per `publish` / `publish_market` batch; all sequences `< 2^63` |
| Consumer & borrow limits | `1..=32` registered consumers (`M`); `1..=1,048,576` concurrent outstanding `RecordBorrow` guards (`B`) per `Subscriber<B>` |
| Record slot widths | `512` bytes (8-byte aligned) for market (`kind 1`: `MarketRecord` / `MarketExactRecord`) and report (`kind 3`: inline `ReportRecord` / `OwnershipRecord`) banks; `1,024` bytes (8-byte aligned) for intent (`kind 2`: inline `IntentRecord`) banks; slot index `(sequence - first_seq) & (capacity - 1)` |
| Producer page atomics (`4096 + ...`) | `+0`: `published` (`first_seq - 1` initially); `+128`: `lifecycle` (`3` Active, `4` Frozen); `+256`: `cutover_seq`; `+384`: `membership_version`; `+768`: `successor_ring_epoch`; `+896`: frozen `membership_version` |
| Cursor page atomics (`4096 + ...`) | `+0`: `read`; `+128`: `applied`; `+256`: `released`; `+384`: `lifecycle` (`3` Active, `4` Quiescing, `5` Quiesced); `+512`: diagnostic `outstanding` count; `+896`: `quiesced_seq` |
| Shared-memory `Arena` (`1..=4` classes) | Contiguous after `SLOTS + capacity * record_size`; strictly increasing `payload_limit` in `193..=65,536` bytes (`1..=65,536` for oversize intent/report arena payloads validated by `tickwire-ipc`); `block_bytes` rounded up to 128-byte multiples (`128`-byte `ArenaBlockHeader` + payload, `<= 65,664`); total blocks across classes `<= capacity` |

## Core Invariants

* **Gated reclamation from pending `JOIN` onward**: Calling `Publisher::join(sub)` immediately installs a `Member` with `baseline = published` and `released = published`, bumps `membership_version` with a `Release` store, and invalidates `cached_min`. A proposed batch ending at `last` can be claimed only when `last - min_released <= capacity` across all registered members (both pending and active). When `observe_release` advances an active member's watermark, `Producer` keeps `cached_min` as a conservative lower bound and recomputes the true minimum across mapped cursors only when `last - cached_min > capacity`, avoiding unnecessary cross-process cursor loads on the fast path.
* **All-or-nothing batch publication and arena safety**: `Publisher::publish` rejects raw market records carrying external arena pointers (`payload_kind == 2`) so safe callers cannot forge references into mutable arena blocks; `publish_market` allocates external depth blocks (`> 12` levels), refreshes active cursors, reclaims retired arena allocations with `allocation.sequence <= min_released`, encodes and validates every record and smallest-fitting `ArenaBlockHeader` in scratch memory, claims the contiguous slot range, writes all arena blocks and ring slots, and only then executes a single `store_u64_release(PUBLISHED, claim.last())`. Any validation, arena-exhaustion (`Error::ArenaExhausted`), or ring-full (`Error::Full`) error rolls back every reserved arena block and aborts the claim without advancing `published`.
* **Non-escaping `RecordBorrow` guards, inline zero-copy views, and prefix-only watermark advancement**: `Subscriber::borrow` `Acquire`-loads `PUBLISHED`, reserves a completion slot in `Reader<B>`, verifies the slot's leading 8-byte sequence (entering `start_quiesce()` and returning `MappedError::Layout` on mismatch), `Release`-stores `read`, and returns `RecordBorrow<'_, B>`. `RecordBorrow` stores `NonNull<[u8]>` rather than `&'a [u8]` so no Rust reference can outlive `Drop` and alias a subsequently reused slot; `bytes(&self)`, `as_market_record(&self)`, `as_market_exact_record(&self)`, `as_market_state(&self)`, and `depth_payload(&self)` tie the returned reference lifetime strictly to `&self` (enforced by `E0515` and `E0505` `compile_fail` doctests). Because slots start at `SLOTS = 8192` with `512`-byte or `1,024`-byte stride on a 4,096-byte page-aligned mapping, every slot satisfies 8-byte alignment, allowing consumers to borrow `&MarketRecord`, `&MarketExactRecord`, `&ReportRecord` (`ZeroCopyRecord`), and `&IntentRecord` (`IntentRecord::from_aligned_slice(guard.bytes())`) directly in place with zero heap allocation and zero disk I/O. Dropping a guard marks its sequence released in the `B`-slot completion table and advances the cursor's `released` atomic *only* across contiguous completed sequences (while `apply(sequence)` independently advances the contiguous `applied` business prefix). Calling `mem::forget` on a guard permanently retains its completion slot and freezes `released`, safely stalling producer wrap-around rather than risking use-after-reuse.
* **Compile-time `crc32` feature gate (`default = []`)**: By default (`not(feature = "crc32")`), `Publisher::publish_market` clears checksum flag `0x08` on `RecordHeader.flags`, writes zero `record_crc32c` / `payload_crc32c` fields into aligned scratch buffers (`[AlignedSlot; 64]`), and skips CRC32C passes over ring slots and `ArenaBlockHeader` blocks; enabling `--features crc32` restores full hardware-accelerated `crc32c` / `crc32c_masked` computation and verification.
* **Ordered multi-counter cursor sampling**: Whenever `Publisher::activate_join` or `cursor_watermarks` inspects a subscriber's cursor page, it `Acquire`-loads `applied` and `released` *before* loading `read` last, then checks `applied <= read <= published` and `released <= read`. Because the subscriber advances `read` before exposing a guard to `apply` or `Drop`, loading `read` last ensures a single monotonic prefix covers both earlier samples without locking.

## Operations and Failure Semantics

* **Verified cursor detachment (`Quiesced`)**: Socket EOF, control timeouts, or unverified control packets never lift a reader's reclamation gate. To detach cleanly, the subscriber calls `start_quiesce()` (idempotently setting cursor `lifecycle = 4` and blocking new `borrow()` calls), drops all outstanding `RecordBorrow` guards so `outstanding == 0` and `released == read`, and calls `quiesced()`, which `Release`-stores `quiesced_seq = read` followed by `lifecycle = 5`. `Publisher::detach` (and `detach_registered`) `Acquire`-loads the *actual registered cursor mapping* to verify `lifecycle == 5`, `read == released`, `applied <= read <= published`, exact equality with the reported `Watermarks`, and `quiesced_seq == read` before clearing the member slot and bumping `membership_version`.
* **Two-phase bank freeze for ring succession**: `prepare_freeze(successor, cutoff)` pins a strictly higher `successor_ring_epoch` and `cutoff >= published` (rejecting any subsequent batch claim with `last > cutoff`). Once `published == cutoff` with no `pending` write claim, `freeze()` transitions the bank to `Lifecycle::Frozen`, writing `cutover_seq`, `successor_ring_epoch`, frozen `membership_version`, and finally `store_u64_release(LIFECYCLE, 4)`. After freeze, no further writes can occur on the bank, while existing `RecordBorrow` guards continue reading their immutable slots safely.

## Cost Accounting and Empirical Benchmarks

* **Startup vs. per-event cost**: `memfd` allocation, sealing (`0x17`), `mmap`, and cursor registration happen exclusively during startup, `JOIN`, or `DOP_LOGIN` / `DOP_ECHO` onboarding. Per market tick, order intent, or execution report, publishing writes one `512`-byte or `1,024`-byte slot (`+` optional SHM arena block when `payload_kind == 2`) and one `Release` store (`0` heap allocations, `0` syscalls, `0` disk operations, `0` clock reads); `Subscriber::borrow` + zero-copy view + `Drop` performs `0` heap allocations, `0` syscalls, `0` clock reads, `0` stack slot copies, one `Acquire` load on `PUBLISHED`, and `Release` cursor updates (`read` and `released`). When a reader lags by `capacity` slots (`Error::Full`) or exhausts `B` concurrent borrows, publication or borrowing returns an explicit backpressure error without overwriting live slots.
