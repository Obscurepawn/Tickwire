# Shared-Memory Broadcast Ring, Arena Reclamation, and Cursor Gating

`tickwire-shm` implements the single-producer, multi-consumer shared-memory broadcast protocol (`Producer`/`Reader` pure state machines and `Publisher`/`Subscriber` mapped SDK) over single-writer Linux `memfd` mappings. One `Publisher<M>` owns a fixed-generation bank (resource kinds `1..=3`: market, intent, or report) and coordinates up to `M <= 32` independent `Subscriber<B>` consumers, each exporting its own 8,192-byte single-writer cursor mapping (`resource_kind = 4`). Rather than letting slow consumers suffer silent ring overwrites and torn reads, the publisher gates slot and depth-arena reclamation on the minimum `released` watermark across all registered consumers—including pending `JOIN` registrations from the instant their baseline cut is reserved.

`tickwire-shm` owns batch slot reservation, optional size-segregated depth-arena allocation, non-escaping `RecordBorrow` lifetime guards, out-of-order release/application prefix tracking, and cursor-verified detachment/freeze transitions. `tickwire-shm-sys` enforces OS `memfd` seals and aligned 64-bit acquire/release operations, `tickwire-ipc` validates record framing and payload semantics, and `tickwire-join` / `tickwire-control` authenticate peer processes, transfer file descriptors, and link successor ring epochs.

## State Model and Bounds

A mapped bank begins with an immutable 4,096-byte `ResourceHeader` (`offset 0`), followed by a 4,096-byte producer atomic page (`offset 4096`), contiguous fixed-width ring slots starting at `SLOTS = 8192`, and—for depth-enabled market banks (`resource_kind = 1` with feature bit `0x02`)—up to four contiguous size-classed external depth arenas immediately after the slot array. Each subscriber cursor is an independent 8,192-byte mapping with its `ResourceHeader` at `offset 0` and 128-byte-isolated `u64` atomic watermarks in page 1 (`offset 4096`).

| Region or Parameter | Layout / Enforced Bound |
| --- | --- |
| Ring capacity & batch size | Power-of-two `capacity` in `64..=1,048,576` (`2^6..=2^20`) slots; `1..=64` records per `publish` / `publish_market` batch; all sequences `< 2^63` |
| Consumer & borrow limits | `1..=32` registered consumers (`M`); `1..=1,048,576` concurrent outstanding `RecordBorrow` guards (`B`) per `Subscriber<B>` |
| Record slot widths | `512` bytes for market (`kind 1`) and report (`kind 3`) banks; `1,024` bytes for intent (`kind 2`) banks; slot index `(sequence - first_seq) & (capacity - 1)` |
| Producer page atomics (`4096 + ...`) | `+0`: `published` (`first_seq - 1` initially); `+128`: `lifecycle` (`3` Active, `4` Frozen); `+256`: `cutover_seq`; `+384`: `membership_version`; `+768`: `successor_ring_epoch`; `+896`: frozen `membership_version` |
| Cursor page atomics (`4096 + ...`) | `+0`: `read`; `+128`: `applied`; `+256`: `released`; `+384`: `lifecycle` (`3` Active, `4` Quiescing, `5` Quiesced); `+512`: diagnostic `outstanding` count; `+896`: `quiesced_seq` |
| Market depth `Arena` (`1..=4` classes) | Contiguous after `SLOTS + capacity * 512`; strictly increasing `payload_limit` in `193..=65,536` bytes; `block_bytes` rounded up to 128-byte multiples (`128`-byte `ArenaBlockHeader` + payload, `<= 65,664`); total blocks across classes `<= capacity` |

## Core Invariants

* **Gated reclamation from pending `JOIN` onward**: Calling `Publisher::join(sub)` immediately installs a `Member` with `baseline = published` and `released = published`, bumps `membership_version` with a `Release` store, and invalidates `cached_min`. A proposed batch ending at `last` can be claimed only when `last - min_released <= capacity` across all registered members (both pending and active). When `observe_release` advances an active member's watermark, `Producer` keeps `cached_min` as a conservative lower bound and recomputes the true minimum across mapped cursors only when `last - cached_min > capacity`, avoiding unnecessary cross-process cursor loads on the fast path.
* **All-or-nothing batch publication and arena safety**: `Publisher::publish` rejects raw market records carrying external arena pointers (`payload_kind == 2`) so safe callers cannot forge references into mutable arena blocks; only `publish_market` can allocate external depth blocks (`> 12` levels). `publish_market` refreshes active cursors, reclaims retired arena allocations with `allocation.sequence <= min_released`, encodes and validates every record and smallest-fitting `ArenaBlockHeader` in scratch memory, claims the contiguous slot range, writes all arena blocks and ring slots, and only then executes a single `store_u64_release(PUBLISHED, claim.last())`. Any validation, arena-exhaustion (`Error::ArenaExhausted`), or ring-full (`Error::Full`) error rolls back every reserved arena block and aborts the claim without advancing `published`.
* **Non-escaping `RecordBorrow` guards and prefix-only watermark advancement**: `Subscriber::borrow` `Acquire`-loads `PUBLISHED`, reserves a completion slot in `Reader<B>`, verifies the slot's leading 8-byte sequence (entering `start_quiesce()` and returning `MappedError::Layout` on mismatch), `Release`-stores `read`, and returns `RecordBorrow<'_, B>`. `RecordBorrow` stores `NonNull<[u8]>` rather than `&'a [u8]` so no Rust slice reference can outlive `Drop` and alias a subsequently reused slot; `bytes(&self)` and `depth_payload(&self)` tie the returned slice lifetime strictly to `&self`. Dropping a guard marks its sequence released in the `B`-slot completion table and advances the cursor's `released` atomic *only* across contiguous completed sequences (while `apply(sequence)` independently advances the contiguous `applied` business prefix). Calling `mem::forget` on a guard permanently retains its completion slot and freezes `released`, safely stalling producer wrap-around rather than risking use-after-reuse.
* **Ordered multi-counter cursor sampling**: Whenever `Publisher::activate_join` or `cursor_watermarks` inspects a subscriber's cursor page, it `Acquire`-loads `applied` and `released` *before* loading `read` last, then checks `applied <= read <= published` and `released <= read`. Because the subscriber advances `read` before exposing a guard to `apply` or `Drop`, loading `read` last ensures a single monotonic prefix covers both earlier samples without locking.

## Operations and Failure Semantics

* **Verified cursor detachment (`Quiesced`)**: Socket EOF, control timeouts, or unverified control packets never lift a reader's reclamation gate. To detach cleanly, the subscriber calls `start_quiesce()` (idempotently setting cursor `lifecycle = 4` and blocking new `borrow()` calls), drops all outstanding `RecordBorrow` guards so `outstanding == 0` and `released == read`, and calls `quiesced()`, which `Release`-stores `quiesced_seq = read` followed by `lifecycle = 5`. `Publisher::detach` (and `detach_registered`) `Acquire`-loads the *actual registered cursor mapping* to verify `lifecycle == 5`, `read == released`, `applied <= read <= published`, exact equality with the reported `Watermarks`, and `quiesced_seq == read` before clearing the member slot and bumping `membership_version`.
* **Two-phase bank freeze for ring succession**: `prepare_freeze(successor, cutoff)` pins a strictly higher `successor_ring_epoch` and `cutoff >= published` (rejecting any subsequent batch claim with `last > cutoff`). Once `published == cutoff` with no `pending` write claim, `freeze()` transitions the bank to `Lifecycle::Frozen`, writing `cutover_seq`, `successor_ring_epoch`, frozen `membership_version`, and finally `store_u64_release(LIFECYCLE, 4)`. After freeze, no further writes can occur on the bank, while existing `RecordBorrow` guards continue reading their immutable slots safely.

## Verification and References

```sh
cargo test --locked -p tickwire-shm -p tickwire-shm-sys
cargo clippy --locked -p tickwire-shm --all-targets -- -D warnings
```

Automated tests cover empty, full, and wrap-around rings, slowest-peer backpressure, pending `JOIN` retention, multi-record atomic batches, depth-arena class selection and rollback, out-of-order `Drop` and `apply`, leaked guards, forged detach rejection, and `cutoff` freeze boundaries. The Linux multi-process fan-out test drives 1, 2, 4, 8, 16, and 32 concurrent reader processes verifying every byte of 1,024 512-byte records.
