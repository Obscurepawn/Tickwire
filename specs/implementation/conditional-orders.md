# Conditional orders, parent identity and leg liability

The original `SpotList` or `Algo` admission fixes one parent and up to three potential legs. The parent does not reserve principal a second time. Each leg retains its original order liability. A later native child may bind to a leg already admitted. Parent acknowledgement, trigger, terminal and unknown observations persist as separate facts. A terminal parent does not close child quantities, fills, fees or reservations. An exact repeated parent observation does not advance the ledger. [Structure reducer](../../crates/tickwire-account/src/structures.rs) · [Conditional-order tests](../../crates/tickwire-account/tests/conditional.rs)

A structure observation uses venue-event schema 2, body tag 5. The decoder checks product, original intent and epoch, parent identity, maximum members and unique children. A parent acknowledgement prevents a later local no-output abort. An acknowledgement received after such an abort restores original leg liabilities and freezes the account. Conflicting native IDs preserve the original binding and freeze the account. Cancel-list and cancel-algo check the scope, instrument, original parent and every leg's current manager and revision at admission and again before output. Replaying a historical handover installs the recorded manager and revision. ## Report provenance

The Binance input owner binds private parent reports and REST/WS parent responses to the registered command and actual session. It syncs input before publishing account effects. Spot member lists establish membership. Individual order status comes from actual order reports. A USD-M native child must be bound through a known parent. An unidentified earlier child is quarantined, and previously assigned native IDs cannot be reassigned. A missing child ID accompanied by a non-zero trigger field or an actual order type leaves the outcome unknown. Repair after a torn account append uses the original input key. [REST structure responses](../../crates/tickwire-binance-account/src/rest/structure.rs) · [Private structure normalization](../../crates/tickwire-binance-account/src/structure.rs)

Late acknowledgements, fills or fees that contradict an abort restore reduction reservations from the original durable order specification. Remaining quantity derives from the original quantity less actual booked fills, including the new fill where applicable. No return message can grant a larger reduction amount or select a different side or position mode. The account stays frozen pending external reconciliation.

## Proving a potential algo leg was never created

The read-only parent queries are Spot `/api/v3/orderList` and USD-M `/fapi/v1/algoOrder`, charged to the structure-query quota. Input tag 21 retains the parent query, clock domain and original response. Recovery reparses that response and compares the derived events. Each *created* child requires its own native order query and contiguous trade-history pages from the initial cursor. Fee closure requires the reported cumulative quantity to agree exactly with all trade pages. A parent terminal response, member list or aggregate `actualQty` cannot produce a child trade or close fees. [Parent queries](../../crates/tickwire-binance-account/src/reconciliation/structures.rs) · [Trade coverage](../../crates/tickwire-binance-account/src/reconciliation/trades.rs)

For USD-M, the parent query must report CANCELED, EXPIRED or REJECTED, an explicitly empty `actualOrderId`, absent or empty `actualType`, absent or zero `actualQty`, and present, zero `actualPrice` and `triggerTime`. Retained history must contain no conflicting child, trigger or fill. The verified cut binds physical writer, baseline, history, ledger and state to the input prefix, private connection and gap generation. The parent query precedes all three current snapshots. Each potential parent needs its own qualifying query. A closure changes the ledger, so the next parent's committed closure requires fresh snapshots. [Closure verifier](../../crates/tickwire-binance-account/src/reconciliation/structure_closure.rs)

Account tag 16, `UncreatedAlgoClosed`, has 13 fields. They bind scope, account epoch, ledger position, baseline, preceding history, input stream and sequence, state and coverage digests, structure ID, original intent, command digest and native parent ID. The 25-field canonical closure is bounded at 4,096 bytes and references one parent query and three snapshots by sequence, byte length and hash. A generic fact append cannot grant this closure. The dedicated gateway verifies the evidence, builds a candidate, syncs the record and publishes it. An exact historical retry reuses the old record. Conflicts freeze. [Record layout](../../crates/tickwire-account-codec/src/codec.rs) · [Closure object and tests](../../crates/tickwire-binance-account/src/reconciliation/structure_closure/tests.rs)

The closure removes only the potential leg's liability and closes its fees. It changes no cash balance, actual position or venue shadow capital. The account remains frozen. A late child revokes the uncreated state, restores remaining liability from the original specification, retains the original closure for audit and freezes the account. On restart, the account reads the closure object and matching input prefix. The controller obtains new snapshots before reactivation.

## State-digest compatibility

Without structure evidence, the original account-input and strategy-order digests stay at v1. The first accepted structure observation advances them to v2 and adds a bounded structure digest. Its preimage starts with `tickwire.conditional-state.v1`. It sorts parents by internal ID, keeps legs in their original command order and sorts children by original client ID. Integers are little-endian and text is length-prefixed. The first durable uncreated-leg closure advances the outer digests to v3 and the inner domain to `tickwire.conditional-state.v2`. The additional bits and closure digests preserve proof history even if a later child restores the liability. [Digest implementation](../../crates/tickwire-account/src/structures.rs)
