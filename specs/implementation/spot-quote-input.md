# Public spot top-of-book input

Bybit spot uses `stream.bybit.com:443/v5/public/spot` and `orderbook.1.SYMBOL`. OKX spot uses `ws.okx.com:443/ws/v5/public` and `bbo-tbt`. Each connection subscribes to one instrument and delivers replacement snapshots. Tickwire verifies the TLS hostname and waits for the matching subscription acknowledgement, symbol and channel. These public streams require no trading credentials.

`tickwire-md --spot-quotes FILE` writes newline-delimited notices for inspection. Each quote carries the venue ID, native symbol, instrument and version, connection epoch, venue sequence, exchange time, process-relative monotonic receive time, and optional bid/ask in integral ticks/lots. Bybit also supplies its update ID. An empty side clears that side. Each process starts its connection epochs at one. Within a connection Tickwire applies complete snapshots in WebSocket delivery order. Each accepted snapshot counts as an observation even if the price or native sequence repeats. Bybit can resend an unchanged L1 after three seconds with the same update ID. A service restart can produce a snapshot with update ID 1. OKX can resend its latest snapshot after about a minute without a change. Its predecessor-sequence continuity rules apply to incremental channels. Tickwire retains native IDs for attribution and orders its own stream by SHM sequence. [Bybit orderbook](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook) · [OKX order book channel](https://www.okx.com/docs-v5/en/#order-book-trading-market-data-ws-order-book-channel)

For a strategy topic, the typed source accepts the publisher’s native monotonic clock and hands an owned fixed-size update to the single topic owner. The owner publishes an exact BBO (type 265) and aggregate feed state (type 261) on the existing shared-memory ring. Each admitted strategy joins its own cursor and starts from a matching snapshot. `MarketView::best_quote()` exposes the tick/lot pair, source ID, native sequence, source epoch and timestamps. Read the quote only while `continuous()` and its own feed state report live, and use `state_age_ns(QUOTE, now)` for the trigger's freshness budget. `best_bid()`, `best_ask()` and `quantity()` remain unknown for these topics because they describe covered depth. The raw Bybit update ID is available on the diagnostic stream. The shared BBO record carries Bybit’s cross-sequence.

An active strategy receives one `on_market` callback for each fresh two-sided observation consumed from the live ring. Type 261 carries `source_schema_id = 0x42424f31` (`BBO1`) on a quote-only topic. The owner publishes the exact quote at sequence S and its live FeedState at S+1, with the same ingress time. The SDK makes the decision at S+1, after both records have been applied. The trigger refers to S+1. A stale pair, a future ingress time or an observation older than the strategy's maximum age generates zero callbacks. The first valid observation after reconnect follows the same rule. Installing a JOIN snapshot initializes the replica without invoking the strategy. Depth topics retain their covered bid/ask callback condition. Replay uses the same eligibility check with the recorded decision time.

The live spot account executor joins the same SHM topic with its own authenticated cursor. A fresh two-sided JOIN snapshot can establish the first policy mark. The snapshot stores the feed and quote as member rows 1 and 2 and carries the original ring sequence in `last_instrument_event_seq`. The executor uses that ring sequence as the trigger. During live delivery it withholds the mark at S and publishes it at S+1. If a poll budget stops at S, the executor denies a pending risk-increasing order at its first-write check. A later intent can reference S+1 after the executor consumes it. The runtime also checks the market-data session lease and the monotonic receive and publish times. [Execution source](../../crates/tickwire-market-source/src/shm.rs) · [Real JOIN and split-pair test](../../crates/tickwire-spot-runner/tests/reconcile_cli/market.rs)

A disconnect, invalid frame, rejected subscription or heartbeat timeout makes the source unavailable. The client starts a new connection after bounded backoff. A heartbeat carries no fresh price. A missing side or crossed snapshot also closes the shared topic’s live gate. The publisher preserves the last exact observation’s ingress time while marking it stale. A later two-sided uncrossed snapshot can restore the source and resume SDK callbacks. An execution policy that has already invalidated this feed generation requires a fresh generation before it accepts market triggers again.

The socket reader hands records to the topic owner through a blocking queue with capacity one. If the owner stalls, the reader eventually stops reading the socket. Disconnect detection and kernel-buffer residence then have no fixed delay bound. Ingress is the monotonic time of the user-space read, and freshness uses that clock. A failed ring publication stops the owner and requires a replacement bank.

The source decoder borrows JSON strings from a bounded WebSocket payload, parses at most one level per side and uses checked decimal arithmetic. Publication uses a fixed number of 512-byte records independent of the subscriber count. TLS, WebSocket framing and the optional diagnostic JSON output can allocate and block. Full cache and snapshot allocation happens outside quote publication. The tests check source fields, stale marking, fresh connection epochs, shared-memory snapshot/live delivery and unknown depth. These are correctness checks, not latency measurements.
