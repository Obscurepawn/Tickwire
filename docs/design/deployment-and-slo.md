# 生产部署、容量与完整链路 SLO

版本：v0.3 · 2026-10-20。此文固定参考部署 `TW-LD-ASYNC-16x2-v1`，其全部数值见 [deployment-reference-v1.json](../../specs/contracts/deployment-reference-v1.json)。它是可执行资格验证的设计输入，不是用户现有机器、账户资金或已经跑出的成绩。

默认生产路径为单写 exec、本地 `durable_intent` 和后台异步复制。逐单不经过 Raft，也不等待远端副本；控制面三副本共识只负责配置、发布和执行权协调。具体恢复保证见[复制与接管](replication-and-failover.md)。

## 1. 固定参考拓扑

| 主机 | 角色 | CPU / RAM / 存储 / 网络参考 | 故障域 |
|---|---|---|---|
| host-a | 主交易机；2 md、2 exec、最多16 Active+16 Shadow；本地日志与控制 voter | 64物理核、256GiB、16TiB可用持久容量、25Gbps | zone-a |
| host-b | warm standby；异步完整日志/闭包、只读重放、预热行情、独立 guardian、控制 voter | 与A同级，预留全量接管资源 | zone-b |
| ctl-c | 第三个有状态控制 voter、独立控制/隔离代理 | 8物理核、32GiB、256GiB可用持久容量、1Gbps | zone-c |

三个控制 voter 都保存完整控制日志和引用的控制配置和发布文件；C 不保存订单 WAL，不作为数据副本。A/B 位于不同主机、电源和网络故障域；位置选择通过 Binance 实际可用入口测量，文档不虚构交易所机房地址。

这套配置允许一个交易主机进程故障后恢复，也保留异机接管流程；异步副本缺少原主可能发送的尾部时必须等待完整源存储/封口证据或保持 Frozen，不能把“两台机器”解释成任何故障都能无损切换。可选 SyncReplica 需要显式修改提交模式和验收网络等待，不能在故障时偷偷降级。

## 2. CPU、内存和 I/O 隔离

参考CPU编号用于配置示例和验证器；真实机器必须导出物理核、SMT邻居、NUMA、网卡队列与中断映射，重新绑定后复验，不直接复制编号。

| 参考核 | 用途 |
|---|---|
| 0–7 | OS、IRQ、控制服务和非热任务 |
| 8–9 | 两个产品的 md 发布循环 |
| 10–11 | 两个账户风险域的 exec 单写循环 |
| 12 | guardian |
| 13–14 | journal/replicator 服务；必要工作线程从48–63预算分配 |
| 15 | recorder/采集中继 |
| 16–31 | 16个Active策略的专用计算核 |
| 32–47 | 16个Shadow/升级实例的专用核 |
| 48–63 | 检查点、输入持久化、指标和预留；不能未经核算再塞入交易实例 |

热线程与其SMT兄弟不共置竞争任务；同一低延迟路径优先位于经过验证的NUMA本地组。跨NUMA时，比较远端共享读取和本地复制副本的完整延迟，形成另一份资格报告。使用 cgroup v2 约束CPU集合、私有内存、PID和I/O，锁页/预触页结果必须检查。[Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)

每交易主机256GiB的独立物理内存预算：SHM 8GiB；策略私有64GiB；md私有16GiB；exec私有32GiB；journal/输入缓存48GiB；控制/guardian/指标16GiB；OS/I/O24GiB；未分配余量48GiB。合计256GiB。SHM按物理页计一次，不能把每个消费者的映射RSS再相加成实际用量；同时检查创建者memcg收费和hugetlb预算。大页可作为已验证部署选择，不默认忽略其独立资源限制。[Linux HugeTLB](https://docs.kernel.org/admin-guide/mm/hugetlbpage.html)

持久介质必须有可验证的掉电语义，文件系统和控制器组合运行断电/重启测试。参考连续写入能力至少2GiB/s；本地提交目标 p99≤200µs、p99.9≤800µs，必须在包含输入日志与后台复制的负载下测量。不能用设备空闲时的单次 `fsync` 成绩代替系统结果。

## 3. 共享内存与多策略容量

参考为两个 `NormalizedMarket` 交易topic，每个产品一个，消息类型区分 depth/BBO/trade/markPrice。最大32个策略实例包含16个Active和16个Shadow；每topic最多40个消费者，包含策略、exec和已计入预算的内部消费者。新增策略必须先通过准入，不能侵占现有策略的保留资源。

| 资源 | 精确容量 |
|---|---|
| Market | 每topic 4 banks；每bank 65,536×512B槽位＋256MiB arena＋8KiB元数据 |
| Market cursor | 2 topics×4 banks×40 consumers×8KiB |
| Intent | 每策略实例/风险域每方向2 banks，每bank 4096×1024B＋8KiB元数据 |
| Report | 每策略实例/风险域每方向2 banks，每bank 8192×512B＋8KiB元数据 |
| SPSC cursor | 每个bank独立8KiB资源，不能用同一个可写对象保存全部消费者游标 |
| 快照 | 2 md＋2 exec，共4个owner；每owner最多8个64MiB对象，共2GiB |
| 配置投影 | 每主机最多128个对象，每对象4MiB内容＋4KiB资源头；包含准备、当前及退休中的对象 |

64个策略—风险域对的全部bank/cursor为 **3,496,542,208 B**；加2GiB快照后为 **5,644,025,856 B**，纳入 **8,589,934,592 B（8GiB）** 的SHM上限，再为配置投影预留537,395,200B，为独立采集中继预留268,435,456B，总承诺为6,449,856,512B，剩余 **2,140,078,080 B** 不是无限扩容许可。完整布局与计算以 [IPC ABI](ipc-abi.md)为准。

Market银行轮换与SPSC replacement分别计数。新旧策略共存已经进入32实例预算；超过并存上限的下一批发布必须等待上一批退役或经过新的容量变更，不能重复计算空闲槽位。旧bank有合法读者时继续占预算，耗尽按照IPC契约失效关联topic，不覆盖活引用。

参考Market高水位49,152条，停止普通claim水位57,344条；发布batch最多64条/4MiB arena。arena每个大小类独立监测，不能只看ring空位。单topic持续50,000事件/s、3倍100ms突发纳入验证；合法大报文的混合分布另按字节预算测试，不把平均长度当最大值。

## 4. 持久化和保留预算

参考负载为总100,000业务事件/s、32个同时保留输入顺序的策略实例、1,000个模拟订单意图/s。对容量取1024B平均规范化行情、64B输入引用、4096B平均意图日志，并加25%帧/索引余量：

```text
trace_rate = (100000×1024 + 100000×32×64 + 1000×4096)×1.25
           = 389120000 B/s
checkpoint_rate = ceil(32×256MiB / 60s)
                = 143165577 B/s
nominal_disk_rate = 532285577 B/s
6h_reference_bytes = 11497368463200 B
```

规范化事件内容可以按哈希存一份，策略日志记录实际合并顺序的引用，不能每个策略再存一份完整行情而仍沿用这个预算。每策略检查点最大256MiB、参考间隔60s；采用版本化增量或不可变视图，生产者暂停预算100µs，不能在热线程同步复制256MiB后宣称没有影响。

6小时是在线保留容量参考，30天是归档参考，均不是法律合规期限。未知订单、发布操作和恢复闭包仍有pin时不可按年龄删除。磁盘80%告警、90%停止新增准入与风险，保留事实/撤单空间；数据备机不可用时仍需保留未确认尾部或完整可安装快照，不删除记录维持表面吞吐。

默认异步复制100ms滞后告警，1,000ms禁止新增风险；这不是RPO承诺。策略恢复依赖和可用空间仍可能要求更早冻结。归档、压缩、快照和复制限速都与交易输入共置压力测试，未达到持续带宽的主机不能使用这套配置。

## 5. 明确的时间和授权合同

| 时间 | 默认值 | 含义 |
|---|---|---|
| IPC资源会话心跳/寿命 | 500ms / 3000ms | 资源管理连接存活；超时不证明内存无人访问 |
| exec短执行资格续期/寿命 | 25ms / 100ms | 每次发送检查本机挑战对应的有效期限，不进入逐单网络往返 |
| StrategyGrant寿命 | 60000ms | 授权对象可较长；每次动作仍检查exec短lease、实例健康、代次与风控 |
| 热循环进度报告/疑似停顿 | 10ms / 50ms | 必须由真正的业务循环推进，服务线程心跳不能掩盖策略/exec卡死 |
| 参考意图期限 | 5ms | 过期拒绝，不延长旧报价；策略可按类型选择更短值 |
| 控制Raft心跳/选举 | 50ms / [500,1000)ms | 只作用于低频协调；任期不是交易所fencing |
| 实际隔离总预算 | 5s | 超时保持Frozen，不用一个超时事件宣告旧sender已停止 |
| 有完整证据的恢复总目标 | 30s | 含隔离、重放、对账、授权；缺失源尾部/交易所不可用时不承诺此期限 |
| 配置操作默认期限 | 120s | 到期返回未完成，不能把部分应用当成成功 |

同机打点使用验证过的单调时钟/TSC映射；跨机不直接相减不同主机的monotonic值。日志里的UTC用于关联，不能替代超时计时。使用socket/NIC时间戳时保存采集覆盖与单位。[Linux 网络时间戳](https://docs.kernel.org/networking/timestamping.html)

## 6. 完整生产路径 SLO

服务水平目标（Service Level Objective，SLO）在这里是上线资格门槛。全部目标均待实际测量：

| 指标 | p99 | p99.9 | 完成点 |
|---|---:|---:|---|
| 合格同NUMA活跃轮询IPC | 2µs | 5µs | publish到指定消费者observe，分别记录各消费者 |
| 单个有界策略/执行核心步骤 | 10µs | 25µs | 声明的输入、计算合同与输出边界 |
| 默认完整tick-to-socket | **300µs** | **1000µs** | 完整明文行情到订单相关密文全部交给内核；包含IPC、策略、风险、依赖闭包、本地WAL和socket等待 |
| 显式SyncReplica完整路径 | 2000µs | 5000µs | 再包括指定镜像持久化等待；必须单独验证，不能当默认模式 |

交易所ACK与成交延迟独立采集，不给未经部署测量的固定互联网往返保证。分段分位数不相加充当完整分布。参考低延迟策略的计算预算不意味着任意模型都能达标；新增策略需提交自己的资源与计算合同，在完整共置链路下通过资格测试。

预热10分钟、基线运行至少1小时；每个p99.9分组至少1,000,000个有效样本，不足时延长运行。72小时长跑覆盖发布、回滚、慢消费者、网络/磁盘扰动和主备演练。发生拒绝、过期或背压仍记录尝试与等待，不能只统计成功快单；资格运行不能丢弃延迟样本。

兼容策略原位交接在Shadow就绪、输入追平和外部服务健康的条件下，以1秒作为关闭到重新开放增险的参考目标；Shadow预热时间另报，不藏进“无停机升级”。存量订单与回报持续运行，管理权变更不承诺交易所跨账户原子执行。

## 7. 恢复验收的边界

30秒恢复目标的参考负载上限：4096个活动订单、64个未知意图、100000笔需核查成交，所用查询接口健康且准入后的恢复额度足够。资格报告必须记录实际请求次数、权重和外部耗时；超过该负载或接口不可用时保持安全状态并报告未决项，不在30秒后强制放行。

默认提交模式发生“原盘永久丢失且异步副本缺尾部”时，预期结果是 `EvidenceLost/Frozen`，这是验收中必须观察到的安全行为。只有可验证完整源前缀、或显式SyncReplica对应的完整镜像证明，才能进入新exec放行流程。复制延迟很小与业务事实完整是两种不同证据。

## 8. 配置文件与控制面接口

运行配置、配置API和本地文件刷新见[配置契约](configuration.md)。本参考JSON不是可直接启动的运行配置；[reference.toml](../../config/reference.toml)使用模拟交易所和合成账户，仅用于资格验证。生产模板必须绑定真实主机/NUMA、账户/产品/标的、资本限额、费率/档位/抵押证据、secret引用、实际隔离后端及资格报告。

技术默认值已经明确；真实账户和机器事实是带类型的部署输入，不能由设计者填造。控制API变更必须经过相同schema和跨字段检查；涉及CPU、ABI、bank大小、复制模式或硬件能力的变更需要受控滚动/换代，不能通过热改配置绕开资格验证。
