# 账户恢复对象编码

`tickwire-account-codec` 保存多资产账户的完整基线、目录、风险参数和有序恢复记录。对象采用确定性 CBOR 编码，带独立记录类型、schema 版本和 SHA-256 摘要。编码结果只表示内容身份；写入 WAL 或恢复对象服务并同步成功后，才满足持久化要求。

`CanonicalBaseline::new(snapshot, catalog)` 检查集合容量、重复身份和账户构造条件，按钱包/资产、标的/持仓侧及策略 ID 排序集合，然后编码。对象同时保存原始资产单位、free/locked 与非交易锁定、策略归属、持仓、风险修订、有效期、费用尾额、风险档位和真实钱包可用余额。读取接口返回共享引用，调用者不能修改已摘要的内容。

`CanonicalBaseline::decode(bytes)` 拒绝超长、截断、非最短整数、浮点数、不定长项、未知标签及尾随数据。解析后重新执行语义检查，并要求重新编码的字节与输入完全相同。不同集合顺序只能经构造接口归一化，不能以第二种字节表示通过解码。

恢复记录绑定基线摘要与非零记录序号，内嵌完整规范命令或交易所事件；WAL 组合层负责检查序号连续性。准入记录另保存判断时间和完整 `AdmissionImage`；该数据用于重放比对，不能独立授权发送。中止、费用闭合、外部现金流、外部仓位和归属转移各自保留必要字段，不能转成单资产标量。

基线上限 2 MiB，记录上限 60 KiB，为物理 WAL 的 64 KiB 批次保留帧开销。每个向量在分配前检查成员数量；编码器达到字节上限后停止扩展缓冲区。基线中的每资产归属和每标的策略限额各最多 1024 项，风险档位最多 128 项；单次准入最多包含 3 个订单。超限返回错误，不能截取输入。

验证先覆盖 Spot 和 USD-M 完整字段往返、独立基准样本、集合归一化、边界整数、每个截断位置、畸形长度、重复身份及摘要敏感性。有状态的账户恢复顺序由账户 reducer 和后续 WAL 组合模型检查。
