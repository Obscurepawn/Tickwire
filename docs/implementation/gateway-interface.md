# 持久交易命令与发送协调

`tickwire-gateway::JournaledSender` 由执行进程单独持有，将规范命令、授权、真实业务日志和非阻塞连接组成一个发送状态机。每个连接同时保留一个待发槽，已冲刷但等待响应的意图可以有多个；连接与命令绑定交易所、账户、环境、产品和 TLS 主机名。协议编码通过 `Encoder` 扩展。

## 提交与发送

`submit(record, command, deadline)` 先核对完整命令与 `DurableRecord` 的身份、摘要、代次、截止时间及恢复对象，再准备报文。`Authorization` 负责验证策略权限和风险预算，将完整命令纳入已同步的恢复闭包。`BusinessJournal::commit_intent` 完成后才允许排队。编码或授权失败不会发送；持久化失败使协调器冻结。

`poll(now, budget)` 推进连接与已接纳的输出。每次首次接受应用字节前，同步调用 `Authorization::current_gate(command, record)`，核对当前执行代次、策略/配置版本、租约、行情、账户和恢复状态。该接口同时负责目录、持仓模式、保证金模式、账户权限与风险批准的时效检查；失败返回拒绝，不能使用等待之前保存的许可。接口没有默认放行实现。

TLS 客户端使用正常根证书及绑定的服务器名；禁止 early data。`Encoder` 返回有界、不可变报文，报文摘要必须等于规范命令摘要，主机名必须等于连接绑定。它属于可信的交易所协议实现，负责使业务参数与实际报文一致；协调器不从可变配置补齐业务字段。

## 结果与恢复

`Queued` 表示还没有应用字节被接纳；`AwaitingResponse` 表示完整报文已交给本机 socket。接受任意应用字节后发生期限、连接或协议失败，保留 `Unknown`，不换连接或协议重发。首次接受后继续冲刷同一份报文，不再重新批准同一命令。

确切零接受终态先追加并同步 `AbortedBeforeSend`，然后返回 `Aborted`。日志失败时保持冻结，不发布可释放的中止结果。只有 `Aborted` 可以交给风险账户释放预留。协调器不直接修改资金，也不把传输完成当作订单 ACK。

重复意图只能读取已有状态，不能再次排队；同一意图改变内容为冲突。恢复逐条验证闭包和原始规范命令，未持久中止的意图统一为 `Unknown`，并冻结新的发送。恢复不重建待发网络队列。业务响应关联、交易结果入账与恢复后的对账授权在执行进程中组合。

## 开发验证

先用真实文件 WAL 和本地 TLS 协议服务器验证提交失败不输出、命令/会话不一致、等待时门禁失效、部分接受后断开、零接受记录失败及恢复禁止重发。协议服务器检查真实编码与签名字节。随后根据实际调用顺序建立模型，检查提交先于输出、零接受中止先于释放、Unknown 不重发。
