# 账户对账控制器

`tickwire-app::reconciliation::Controller` 在私有流处于 Receiving 时推进账户对账。初次启动、缺口或账户冻结需要完整对账；健康账户只有存在尚未闭合费用的终态订单时才启动费用维护。已中止订单不在维护集合内，活动订单不会仅因费用尚未闭合触发维护。

`reconciliation.fee_maintenance_interval_ns` 是两轮成功对账之间的最小维护间隔，必须大于零，省略时为 1 秒。维护还要求 REST 发送器空闲；每轮只推进一个订单请求或一页成交，继续使用实际共享额度和 I/O 预算。失败使用已有 `retry_ns`，不会按每个事件循环发送新请求。

维护复用现有完整流程：持久保存 BeginReconciliation，重新取得当前订单集合，查询订单，从 `from_id=0` 读取完整成交分页，核对逐笔成交与终态累计量，再同步 FeesReconciled。随后核对账户、普通挂单、条件挂单三份真实快照，持久激活账户。已有 reader 的冻结边界保持不变；维护期间暂停增险，继续接收回报和执行已获授权的撤查。FILLED 或一笔零手续费本身不释放未知费用尾额。

成功、失败或连接切点改变都会结束当前扫描。下一轮重新加载当前账户订单，即使私有连接和 gap generation 没有变化，也不能沿用上一轮的空集合。离线恢复始终冻结；没有 FeesReconciled 的终态订单仍可显示恢复 Unknown，这不代表在线回报包含 Unknown。
