# 执行内核与外部服务接口

执行内核由一个账户风险域的单写者调用。策略、行情、存储完成和交易所回报都是输入事件；一次方法调用完成候选状态校验后才修改状态。Rust 库不创建线程、不读取系统时间、不持有密钥。

`OrderKey` 包含 venue、account、product 和本域永久唯一的 intent ID。交易请求 ID、交易所订单 ID 和成交 ID 各有独立用途；成交按完整订单身份及 trade ID 去重。Spot 与 Futures 使用独立实例和资本，不跨产品借额。各交易所适配器把协议消息转换为统一事件，内核不解释币安 JSON。

| 模块/接口 | 输入与输出 | 所有权与完成点 |
|---|---|---|
| `Engine<N, T>` | 准入、提交收据、发送尝试、成交、终态、故障事件 | 固定 N 个订单槽；每单固定 T 个成交身份；容量耗尽有明确错误，未对账身份不覆盖 |
| `Journal` | 追加完整 `DurableRecord`，返回绑定订单与序号的 `CommitReceipt`；恢复读取已提交记录 | `append` 成功表示本地模拟持久提交；真实实现还需 WAL seal、同步与恢复闭包证明 |
| `Exchange` | 接收 `OrderRequest`，返回 `NoBytesAccepted`、`PendingResponse`、`MayHaveSent` 或权威回报 | 调用前内核先转为 `MayHaveSent`；只有明确未接收任何可输出字节才允许本地释放 |
| `ConfigStore` | 以 revision 条件写配置 | Mock 关系库提供比较并交换；真实实现可映射到 SQL 事务 |
| `ObjectStore` | 按稳定 key 保存不可变字节，返回内容；同 key 不同内容失败 | Mock KV 提供幂等写、故障注入；恢复依赖对象先保存，再提交引用它的 journal |

发送有两次检查：准入检查当前上下文并预留额度；持久化后发送前再次检查配置、策略代次、执行代次、行情/账户有效性、恢复屏障、租约与意图期限。`Gate` 的时间由调用者显式传入；增险资格要求 `now < deadline`。布尔资格是内部服务验证后的事实，不能直接接受策略提供的值。

订单的业务终态、发送进度、取消尝试独立保存。超时、断连和 not-found 保留可能已发订单的预留，并冻结该共享池增险；等待正常 ACK 的发送中状态本身不触发冻结。部分成交先记现金支出，再保留未成交数量对应的预算及费用尾款；交易所终态包含累计成交，若明细未齐仍保留差额预算。迟到 ACK 不倒退累计数量或终态。成交 ID 缓存满时拒绝继续消费并要求恢复，不能丢掉去重证据后继续交易。

本阶段实现通用的“有界支出订单”执行原语：每个数量单位有最大成本，另有独立费用预留。Spot、Futures 复杂组合保证金由 `tickwire-risk` 计算后接入；原语自身不推断合约减仓或保证金。订单槽和去重身份在本阶段不回收，回收协议属于后续持久检查点工作。

全链路 MockService 测试将串起配置读取、恢复对象写入、行情触发决策、账户预留、journal 提交、交易所接单、成交与恢复。关系库/KV/journal/交易所分别注入失败，明确哪些状态在模拟进程崩溃后保留。Mock 结果覆盖业务状态与服务契约；多进程 mmap、真实介质掉电和网络适配器仍按 P1～P5 单独验收。

真实 reactor 适配器通过 `PendingResponse` 表达正常等待 ACK，通过 journal 的 `Pending` 表达异步持久化未完成；接口调用不要求阻塞等待网络或磁盘。明确超时/断连才报告不确定并触发共享池冻结。
