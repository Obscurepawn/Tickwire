# 恢复标记不能改变持久记录的去重

恢复会给未闭合订单添加保守 Unknown，并冻结账户。这些状态保护新进程，却不是原始 WAL 中的交易所观察。如果重复成交通过“订单或全局冻结是否变化”决定是否增加账本序号，恢复标记便会遮住后续第一次收到的交易所 Unknown。同一组持久记录由在线进程处理时少增加一次，从原始基线重放时多增加一次。

最初的模型轨迹只显示序号 2 与 3。真实文件回归确认资金、剩余责任和准入记录一致；再把基线推到 MAX−2，第三条记录曾在线返回 Duplicate，重开却因序号溢出失败。由此确认问题影响合法日志的再次恢复。主动冻结后接收重复成交附带的新终态异常，也能触发相同差异。

修复在订单内部记录交易所 Unknown、恢复 Unknown 和单调的观察异常。公开 Unknown 仍合并前两者，所有风险拒绝条件保持。持久记录的去重依赖交易所观察造成的订单变化；本地冻结和恢复附加状态不会影响账本计数。上限错误保持原账户状态，已保存的拒绝记录继续阻止恢复，不被过滤。

模型保留完整持久订单投影与账本序号的 `AccountPrefix`，并增加 `SuccessfulPrefixReplays`：只要线上每条记录均成功应用，该公开前缀就能完整重放。已拒绝记录的诊断计算可用于比较在线账户，但实际恢复仍在第一条错误停止。后续扩展应继续保留这两个性质，尤其覆盖真实回报关联、基线切换与恢复激活。
