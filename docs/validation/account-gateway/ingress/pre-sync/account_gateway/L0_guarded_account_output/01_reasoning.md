# 状态与抽象

`account` 表示已发布账户，`candidate` 是提交或中止计算的克隆。Admit 成功同步后才发布 candidate；若追加返回错误，仍保留候选预留并停止，因为完整尾可能存在。中止在写日志前先对 candidate 校验，已有 ACK、Unknown 或成交时不写 Aborted。中止同步失败时保持原账户，同步成功后才发布释放结果。

有序日志保留所有完整记录，逐条恢复。每个 Admit 的规范摘要包含完整命令与准入 image，并由可信闭包绑定基线和该记录之前的历史。模型用不碰撞的记录与前缀值表示这些摘要，不从闭包对象生成缺失日志。所有镜像、身份和 byte codec 的正确性都是具体接口边界，而不是可任意设置的生产放行布尔值。

有限 Spot 账户保存已准入意图、已中止订单、确认、终态及累计量、交易所 Unknown、恢复 Unknown、观察异常、去重后的成交集合和账本序号。每笔不同成交使 base 增加 1、quote 减少 1；未中止且未通过终态累计闭合的订单预留为 2 减已成交数量。重放相同 trade 不重复现金流，新的 Unknown 或终态异常仍应用。ACK 或成交在中止之后到达会恢复剩余责任并冻结账户。

`observedUnknown` 和 `unreconciled` 是持久记录生成的订单状态，`recoveryUnknown` 是恢复后附加的保守标记。重复成交按订单的持久状态是否改变决定增加序号，本地冻结和恢复标记不参加这项比较。`AccountPrefix` 同时比较全部持久订单字段和账本序号；资金由这些字段唯一计算。只排除明确不属于持久记录的恢复标记和本地冻结状态。

`halted` 与 `account.frozen` 分开。halt 会关闭连接、清空 pending 并将非 Aborted 的传输状态改为 Unknown；外部事实仅使账户冻结时，协调器继续处理健康连接。撤单/查询的准入和首次门禁不依赖行情与账户基线新鲜度，但仍依赖命令身份、动作授权、租约、当前代次和请求期限。

poll 按 drive、发送报告、try_send、返回分阶段。drive 只能冲刷此前接受的 TLS 应用前缀；零 I/O budget 在任何 socket 操作前返回 Bounds，不提供 NoBytes。try_send 在零接受时现场取完整门禁，随后再次检查 Instant 截止；已有正数前缀后继续同一报文不重新批准。每个意图保留历史入队次数、接受字节数与已冲刷前缀，后续槽位不会覆盖这些见证。

公共 record_fact 在 halt 后仍可追加健康日志，完整同步后才应用账户；日志 poison 时失败并保持账户。账户拒绝的记录仍在 WAL，恢复检查不能过滤掉它。恢复从完整有序前缀重算账户，再冻结；恢复 entry 保留 Unknown 或持久 Aborted 状态，但 committed capability 为空。

`Replay` 的累计 `ok` 在第一次错误后保持 false，但函数继续计算后面的逐条账户变化，供 `AccountPrefix` 比较在线进程在错误后继续记录结果的状态。真实恢复在第一个错误立即返回；模型只有 `Replay.ok=true` 才能执行 `RecoverOk`，不把后续诊断计算当作恢复成功。`allApplied` 记录公开前缀是否曾返回账户应用错误；`SuccessfulPrefixReplays` 进一步要求此前全部返回成功的前缀可以完整重放，直接覆盖这次 MAX 反例。

模型中的 Aborted 是传输中止历史。迟到 ACK 或成交可以在账户中重新建立责任，而 entry 的传输状态仍为 Aborted；因此不使用“Aborted 状态永远意味着零预留”这一错误性质。检查的是释放动作之前已有零接受证据、候选账户通过校验并完成中止同步。

首次 TLC 检查发现恢复前后账本序号不同；真实 Rust 回归进一步证明，在 MAX−2 基线下系统曾把不可再次重放的后缀返回为 Duplicate。root 与 IPC 独立确认后，账户实现分开两种 Unknown，并为终态异常保存持久标记。原模型、轨迹、普通与上限 Red 均保留；v2 恢复包含序号的强性质，详细归因见 `04_counterexamples.md`。
