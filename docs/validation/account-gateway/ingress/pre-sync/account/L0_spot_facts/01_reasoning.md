# 状态与抽象

`totalBase/totalQuote` 是初始金额加真实现金流；`baseOwner/quoteOwner` 记录各订单原策略的变化，初始资金在未归属桶。`trades` 与 `fees` 是成交与费用记录内容，单独保留事实键及其金额，使“重复不扣款”可以从现金内容而非状态标签检查。

每笔成交数量为 1，报价支出允许 1 或 2；固定原始数量 2 和价格上界 2。费用为接收币扣款，费率 1/2 与两个原子舍入尾额。模型中的本金和手续费剩余量逐式转录 `order_resources`。不构造随机市场上界，也不把所得资产在成交前记入账户。

`terminal` 与 `terminalCum` 分开：终态报告的累计量未与实际逐笔成交相等时，剩余本金继续保留。`closed` 只由终态、累计量和成交明细对齐后的独立费用闭合动作设置。迟到成交与费用记录会重新打开已闭合/中止的责任并冻结；每条真实新事实仍然记账。未知状态只关闭增险，不删除任何订单。

准入先算候选全部资产预算，两个资产均足够才接纳。事实动作在资产不足、费用超界或矛盾终态时更新账务并关闭增险。`NoOpenDeficit` 因而仅检查增险门仍开时的资源余量；无条件非负会错误地禁止实际负债入账。

本级省略身份/单位校验失败的字节细节，以具名 Reject/Conflict 动作表达保留原财务状态并冻结。定点溢出、不同资产精度、策略和目录身份由 Rust 测试覆盖；有限整数域不声称覆盖全部 i128 运算。

有限输入中的 Fill 带空的内嵌费用列表和正常已确认、非终态订单观察；一次 Fill 动作涵盖 apply_fill 与 observe 的完整调用。Fee、Terminal 动作表示随后独立到达的事件，没有把单个事件内部步骤拆成可交错动作。
