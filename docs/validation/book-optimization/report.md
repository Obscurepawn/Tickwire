# 有序数组盘口的批量更新优化

这次修改保留 `Book::apply`、独立 `SequencePolicy`、双侧原子失败和 `Unknown` 覆盖规则。更新在实例内的固定工作区排序，定位结果复用于容量验证、最优价检查和提交；纯改量直接写旧位置，插删只合并受影响的连续区间。小更新没有被统一改成全簿扫描。

旧版为 commit `cd8bde270ac257b296100979621c60c64f965e42`。对照脚本读取该版本的库源码，与当前库分别放入临时独立 crate，再复制同一份基准程序并使用相同编译配置。测量结果对应的库与基准 SHA-256 位于环境文件，复跑时可据此检查代码是否变化。

## 算法与内存成本

每侧更新先按价格排序，检查数值和相邻重复；对已排序的下一项，先检查上次定位之后的旧价位，价格不匹配才二分查找剩余区间。连续价位更新因此不再为每项从整簿重新搜索，价格分散时仍保持对数查找。容量按删除与新增后的最终存活数量验证；删除前缀和第一项正数量更新共同确定最终最优价。

只有双侧计划和最终价差全部验证成功，才修改有效价位。无插删时按已缓存的位置改量；有插删时，将第一处更新到最后一处更新覆盖的旧区间与更新合并到固定数组，净长度变化才移动一次后方数据。删除最佳价再插入一个新的最佳价，合并区间只有一档，未修改的尾部保持原位。序号、水位与新鲜度在双侧价位写入结束后提交。

设每侧已有 `L` 个价位、收到 `K` 项更新，增量最坏比较量为 `O(K log K + K log L)`；插删的合并与移动最多再加 `O(L+K)`。原版的重复检查和旧最优价过滤包含二次循环，逐项插删还会重复移动尾部。排序使用整数全序比较和无分配的 [`sort_unstable_by`](https://doc.rust-lang.org/std/primitive.slice.html#method.sort_unstable_by)。

当前 64 位实现中，两侧有效价位的字段载荷仍为 `32N` 字节，新增工作区为 `16N+32M` 字节，其中 `N` 是每侧容量，`M` 是总更新上限。`N=4096,M=1024` 时新增 96 KiB；工作区在构造时初始化，事件只覆盖实际使用的前缀。多标的轮转带来的缓存影响尚未测量，生产容量要把这部分内存一起计入。快照安装仍使用原实现，本轮没有测量或优化快照。

## 失败测试与正确性

先给旧实现增加测试用比较和搬移计数，再运行确定性工作量约束，获得两个实际失败；单项改量约束在旧实现上通过。它们使用操作计数，不依赖调度或某台机器的纳秒阈值。

| 测试 | 旧版记录 | 当前记录 | 约束 |
| --- | ---: | ---: | ---: |
| 1024 档上 512 项不同价格改量，输入为固定排列 | 273,920 次比较 | 6,188 次比较 | 不超过 16,384 次 |
| 1024 档满容量，64 项删除与 64 项新增交错 | `copy_within` 搬移 126,912 档 | 合并区与盘口写入 128 档 | 不超过 4,096 档 |
| 4096 档上单项已有价位改量 | 通过 | 15 次比较、写入 1 档 | 比较少于 128，搬写不超过 4 |

比较计数覆盖显式比较函数，包括二分、重复检查、排序和旧价过滤；旧版 `max/min` 的比较没有单独插桩。搬移计数不包含输入工作区复制和排序交换；旧版数字只统计 `copy_within`，新版还计入合并区写入与复制。它们用来识别二次比较和重复整尾搬移，完整执行耗时由后面的 release 基准测量。

[Red 日志](red.log)记录退出 101、两个断言失败；[Green 日志](green.log)记录修改后 30 项测试全部通过。原有 8,000 批 `BTreeMap` oracle 和 960,000 次数量查询继续通过。新增边界测试包括双侧满容量整批替换、正反输入顺序、截断边界外 `Unknown`，以及卖侧大批末尾的重复价、负数量、容量超限、交叉价格导致整批失败。失败后买卖两侧和水位均保持原值。大批插删循环的 `alloc/alloc_zeroed/realloc` 计数为零。

两位独立审阅者检查了定位游标、删除前缀、合并区间和提交顺序，未发现待修候选。其中一位另写了独立 `BTreeMap` 差分程序，运行 40,000 个小容量双侧批次：30,822 次成功更新的逐层内容一致，9,178 次容量拒绝保留原双侧内容与水位；所有成功批次的截断覆盖边界保持不变。这个程序已归档为 [`tests/differential.rs`](../../../crates/tickwire-book/tests/differential.rs)，纳入上述 30 项测试；它是正确性样本，不参与延迟统计。

```sh
cargo test -p tickwire-book -- --nocapture
cargo clippy -p tickwire-book --all-targets -- -D warnings
```

## 对照负载与计时边界

主机是 Apple M1 Pro，macOS 15.7，Rust 1.99.1。两版均使用 release 的 `opt-level=3`、`overflow-checks=true`、`lto=thin`、`codegen-units=1`。每个用例先预热 10,000 次，再逐事件采样 200,000 次；共五轮，每轮交换旧版与新版的运行先后。每个负载每个实现合计一百万个计时样本，分位数先逐轮计算。

计时从 `Instant::now()` 开始，覆盖 `apply + view + best_bid + best_ask`，并通过 `black_box` 保留可观察结果；事件生成、输入排列、样本入数组和最终分位数排序在计时区间外。原始时钟观测值不减去空计时区间的均值。两版按相同 seed 和事件次序运行，输入更新条数都为双侧合计。

`batch_apply` 包含每侧 32/512/4096 档、每事件 2/16/64/512 项改量，以及 4 项最佳价插删、256 项成批插删。改量从固定随机起点选择连续 rank，越过末端会绕回；`natural` 保留此生成顺序，`reverse` 翻转输入，`shuffle` 用固定随机序列打乱。成批插删交替删除旧 tick、插入相邻 tick，存活档数保持不变。

额外的 `sparse_apply` 用步长 73 在 512/4096 档中取不同 rank，使改量和插删散布在整簿中；这些深度均为 2 的幂，奇数步长不会重复选中同一 rank。它用于检查相邻价位命中减少后，以及合并区间变宽时的成本。两个程序分别运行，避免互相竞争 CPU。

```sh
python3 crates/tickwire-book/benches/compare.py \
  --samples 200000 --rounds 5 --output /tmp/book-comparison
python3 crates/tickwire-book/benches/compare.py \
  --harness sparse_apply --samples 200000 --rounds 5 \
  --output /tmp/book-comparison-sparse
```

## 五轮对照结果

下表每项是五轮对应分位数的中位数，单位为 ns；没有把五轮样本合并后重新计算分位数。逐轮 p50/p99/p99.9/max 见[统计 CSV](results.csv)，每个分位数的运行间最小/最大值见[汇总 CSV](summary.csv)，源码摘要与环境见[environment.json](environment.json)。

| 每侧 4096 档的负载（更新数为双侧合计） | 旧版 p50 / p99 / p99.9 | 新版 p50 / p99 / p99.9 |
| --- | ---: | ---: |
| 2 项改量 | 84 / 167 / 250 | 84 / 167 / 583 |
| 16 项相邻改量 | 708 / 834 / 2,334 | 167 / 292 / 708 |
| 64 项相邻改量 | 2,875 / 6,000 / 25,750 | 375 / 667 / 1,625 |
| 512 项相邻改量，原顺序 | 36,416 / 69,708 / 280,958 | 2,375 / 7,041 / 15,209 |
| 512 项相邻改量，反序 | 36,417 / 70,292 / 261,458 | 2,583 / 8,291 / 20,583 |
| 512 项相邻改量，输入打乱 | 36,292 / 72,750 / 341,250 | 8,584 / 13,916 / 45,375 |
| 4 项最佳价插删 | 3,875 / 4,333 / 41,625 | 125 / 208 / 250 |
| 256 项近端插删，输入打乱 | 253,083 / 644,334 / 2,746,167 | 11,667 / 19,667 / 49,542 |

最佳价插删的五轮 p50 从 3,750–3,958 ns 降至每轮 125 ns；256 项近端插删从 245,875–255,875 ns 降至 11,209–11,916 ns。这两项改善对应受影响区间的缩小和整尾重复搬移的消除。512 项改量在打乱输入时仍需排序，p50 为 8,584 ns，高于原顺序的 2,375 ns，输入分布会改变收益。

2 项改量的 p50 基本保持 84 ns、p99 同为 167 ns；p99.9 的中位数观测从 250 ns 上升到 583 ns，新版五轮范围为 208–1,292 ns。因此本轮只确认小包没有新增全簿扫描及中位耗时退化，没有确认小包尾延迟改善。空计时区间 p50 中位数为 0 ns、p99 为 42 ns，短包差异受计时量化和运行间干扰影响。

稀疏扩展使用相同编译配置、每轮样本数和五轮交替次序；所有输入均打乱。逐轮统计、运行间范围与代码摘要分别见 [sparse/results.csv](sparse/results.csv)、[sparse/summary.csv](sparse/summary.csv) 和 [sparse/environment.json](sparse/environment.json)。

| 每侧档数 / 散布更新数 | 旧版 p50 / p99 / p99.9 | 新版 p50 / p99 / p99.9 |
| --- | ---: | ---: |
| 512 / 16 项改量 | 500 / 625 / 708 | 667 / 833 / 1,791 |
| 512 / 64 项改量 | 2,042 / 2,334 / 13,667 | 1,375 / 1,625 / 7,709 |
| 512 / 512 项改量 | 29,958 / 46,750 / 110,000 | 8,958 / 11,500 / 41,625 |
| 512 / 256 项插删 | 32,916 / 48,542 / 104,792 | 11,250 / 16,916 / 49,417 |
| 4096 / 16 项改量 | 667 / 833 / 1,625 | 958 / 1,250 / 5,375 |
| 4096 / 64 项改量 | 2,833 / 3,333 / 18,834 | 4,042 / 5,458 / 27,291 |
| 4096 / 512 项改量 | 35,875 / 61,083 / 142,625 | 33,833 / 58,667 / 202,584 |
| 4096 / 256 项插删 | 147,625 / 267,417 / 969,459 | 33,333 / 55,833 / 163,875 |

散布改量削弱了连续定位的收益。4096 档上，16 项与 64 项改量的 p50 分别增加约 44% 和 43%；对应新版五轮范围为 958–958 ns、4,041–4,083 ns，旧版为 667–708 ns、2,750–2,834 ns，退化在每轮都存在。512 项散布改量的 p50 只改善约 6%，p99.9 观测上升。排序、工作区维护和定位共同计入这些数字，目前没有分段测量来确定各自占比。

散布插删仍从一次移动尾部和合并中受益，4096 档、256 项更新的 p50 从 147,625 ns 降到 33,333 ns，约为旧版的 23%。因此当前实现主要改善结构变化和连续价位的大批更新；少量乱序、分散的改量已有可复现退化。后续若增加小批专用分支，选择条件需同时考虑更新数、是否改变结构和分布，并用这组反例负载复验。

开发机未绑核、未隔离其他开发任务；短事件受约 41–42 ns 的计时量化影响，尾部包含调度干扰。这里测量标准化事件进入单标的热盘口后的服务时间，未包含行情解码、跨核排队、策略计算、IPC、存储或网络发送。后续生产验收在目标 Linux 主机增加多标的工作集、开环到达率、积压和拒绝统计。
