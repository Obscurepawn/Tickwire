# 小批乱序盘口更新：定位成本与循环有序边界

最终五轮中，4096 档、双侧合计 16/64 项散布改量的 p50 从 958/4000 降至 542/2000 ns；相邻更新的 p50 保持不变，跨末尾的尾部退化已修复。512 项大批和插删继续纳入相同负载对照。

本轮固定 `df8bd2dfab8193f0a647d17e344ca7ed54577132` 为基线，保留有界数组、双侧原子提交、覆盖与 `Unknown`、独立 `SequencePolicy`。改动只涉及更新计划的选择和价位定位。前一轮结构合并的历史报告保留在[原目录](../book-optimization/report.md)，其中已记录的小批散布退化没有被覆盖。

## 成本来源与实现选择

先在基线的 `prepare_side` 中插入分段时钟，分别观察复制、排序、定位与计划循环、最终计划构建。每个负载先预热 10,000 次，再运行 100,000 个事件；下表为双侧合计的每事件阶段均值，单位 ns。插桩增加了时钟读取，并可能改变编译结果，因此只用它定位成本，最终分位数取未插桩源码。

| 每侧深度 / 双侧更新数 | 复制 | 排序 | 定位与计划循环 | 最终计划 |
| --- | ---: | ---: | ---: | ---: |
| 4096 / 16 改量 | 39.20 | 92.72 | 848.39 | 36.75 |
| 4096 / 64 改量 | 46.67 | 688.92 | 3303.73 | 36.24 |
| 4096 / 512 改量 | 278.47 | 6747.48 | 26220.80 | 39.14 |

[诊断脚本](diagnose.py)从固定 Git 版本构建临时 crate，支持 `suffix`、`full`、`hybrid` 三种定位实验。[基线](diagnostic-baseline.log)的二分范围是上次命中后方的切片。`full` 对每项都在全簿二分，散布变快，但破坏了相邻直接命中；`hybrid` 保留相邻命中，只把二分的边界改为固定全簿。后者的 4096 档、16/64/512 项散布改量，定位与计划阶段分别为 587.49/2178.81/17032.25 ns，512 档密集更新仍保留直接命中。[完整记录](diagnostic-full-search.log)、[hybrid 记录](diagnostic-hybrid-search.log)。源码上，这消除了后一次二分边界对上次定位结果的依赖；本次没有硬件性能计数器，阶段均值只支持选择这个实现进行完整对照。

最终实现采用以下规则：

- 每侧最多 32 项时识别输入顺序。正序保留，反序直接反转；识别结果直接替代排序步骤，避免先扫描、再重复排序。
- 对全部正数量、循环有序的输入，找出唯一断点，将固定工作区旋转，必要时再反转。随后走通用计划，继续复用相邻旧位置。
- 其余小批无序正数量输入尝试直接定位。每项都已存在且价格唯一时，计划只改数量，保留原长度、最优价格和覆盖边界。某项不存在则回到完整排序计划，并重算全部索引。
- 使用局部 64 位标记筛选旧位置低 6 位是否碰撞。碰撞后比较实际价格，只有真实重复才拒绝；32 项的最坏额外比较上限为 496。价格和数量在选择分支前已校验，零数量仍走结构计划。
- 通用计划保留相邻直接命中，二分回退改用全簿固定边界。两侧计划与最终 spread 全部验证通过后才写盘口。

每侧 32 项是针对本轮双侧 16/64 项负载选择的有界阈值，没有宣称它适合所有处理器与行情分布。实例工作区没有增加：64 位实现的 `Book<4096,512>` 仍为 213,096 字节。通用路径复杂度仍为 `O(K log K + K log L)`，插删再加受影响区间与尾部搬移；小批分支最多执行 32 次二分和 496 次精确碰撞比较。

[第一组短跑](exploratory/)把顺序检测叠加到原排序前，4096 档、16/64 项相邻 p50 从 167/375 增至 208/458 ns，未保留；[第二组](exploratory-v2/)仍重复排序，相同 p50 为 187.5/416 ns。[第三组](exploratory-v3/)复用顺序分类，相邻 p50 恢复到 167/375 ns。这些探索均为每负载 20,000 次、两轮，仅用于选择下一次正式实验。

## 正式对照暴露的跨末尾退化

第三组候选 `056d91ef…beb3d` 的完整五轮结果也被保留：[primary](rejected-wrap/primary/results.csv)、[sparse](rejected-wrap/sparse/results.csv)、[源码快照](rejected-wrap/lib.rs)。它改善了散布改量，但相邻负载用 `(start+j)%N` 生成，跨越数组末尾的少数批次呈循环有序。旧候选把它们判为无序，每项独立二分，失去了相邻定位复用。

这套实验中，512 档、16/64 项相邻更新的 p99 五轮中位数从 208/667 增至 334/1375 ns；4096 档、64 项的 p99.9 从 916 增至 2125 ns。512 档、64 项的各轮 p99 旧版均为 667 ns，候选为 1333–1416 ns。这组稳定差异促使新增跨末尾工作量回归。

随后新增确定性跨末尾测试，32 项更新从旧数组末尾开始，要求保留相邻查找的工作量预算。修改前实际记录 418 次比较，超过 250 的上限，测试退出 101。最终代码先旋转循环有序输入；起点 4095/4080、正反两个方向分别记录 111/140/125/125 次比较，写入价位均为 32。未插桩的最终候选另跑完整五轮，下面使用这一套结果。

## 正确性、复现与测量边界

原 30 项测试全部保留，新增 2 项确定性工作量、3 项批次边界、1 项零分配测试，当前共 36 项。第一次 Red 为小批散布 636 次比较超过 480；最终为 422 次，写入 32 个价位。第二次 Red 为跨末尾 418 次超过 250。[初始 Red](red.log)、[跨末尾 Red](red-wrap.log)、[最终 Green](green.log)、[Clippy](checks.log)均保留实际输出。计数器只在测试配置启用，记录指定位置的价格比较和盘口/合并数组写入，不代表 CPU 指令数或全部工作区写入。

新测试覆盖标记碰撞但价格不同、迟到重复、部分定位后发现缺价的成功/容量失败回退、负数量、双侧数组与序号在失败时保持原值、覆盖外 `Unknown`。分配计数包含无序快路和循环旋转：构造、快照、1000 次双侧更新与 view 的 alloc/alloc_zeroed/realloc 均为零。原独立 `BTreeMap` 差分继续通过 40,000 批，其中 30,822 批成功结果逐价相同，9,178 次容量拒绝保持双侧价位和水位。源码由独立审阅者检查了部分计划回退、精确重复检查、循环分类、双侧提交顺序和覆盖语义。

正式比较通过同一个 [compare.py](../../../crates/tickwire-book/benches/compare.py)分别编译基线和当前 `lib.rs`，两个实现使用完全相同的 harness 与 release 参数：`opt-level=3`、`overflow-checks=true`、`lto=thin`、`codegen-units=1`。每负载每轮预热 10,000 个事件，再采样 200,000 个；五轮交替 before/after 执行顺序，每实现每负载合计一百万次计时。结果是各轮分位数的中位数及运行间范围，不把它们称为合并一百万原始样本后的分位数。

机器为 Apple M1 Pro、macOS 15.7、Rust 1.99.1，未绑核、未隔离 CPU。最终两套实验期间，其他协作任务暂停编译与 TLC；操作系统及后台进程仍存在。时钟区间从 `Book::apply` 前开始，直到 `view + best_bid + best_ask` 完成；输入生成、初始化、样本存储与排序均在区间外。数据均为固定种子的标准化合成事件，未包含解码、网络、IPC、策略或持久化。空区间单独测量，保留原始耗时，不减时钟均值；约 41–42 ns 的量化会影响极短负载。

4096 档、16/64 项散布改量的 p50 分别降低 43.4%/50.0%，p99.9 从 3000/15375 降至 1625/7834 ns。对应的各轮 p50 范围为 917–958→542–542 ns、4000–4000→1959–2000 ns；p99.9 范围为 2167–5083→958–2083 ns、14334–16500→7458–8542 ns。512 项散布改量和 256 项散布插删的 p50 也分别降低 27.7%/13.6%。

相邻改量的所有 p50 五轮中位数均保持基线值。此前暴露退化的 512 档、64 项负载，最终 p99 从 667 降至 500 ns，候选五轮 p99 都为 500 ns；p99.9 从 792 降至 625 ns。4096 档、64 项的 p99.9 为 916→875 ns，各轮范围 875–1083→708–1042 ns。两个档数的 2 项更新与 4 项最佳价插删，p50/p99.9 中位数均保持不变。

保留的细小退化出现在 512 档、512 项散布改量：p50 为 8750→8792 ns（+0.5%），p99 为 10000→10084 ns，p99.9 为 24041→24166 ns；各轮 p50 范围为 8750–8875 与 8750–8833 ns，互相重叠。4096 档、512 项自然序的 p99 从 6917 增至 6958 ns。它们继续留在验收负载中，本轮不把约一至两个时钟量化单位的变化解释为确定的处理器机制。

两套空区间的 p50/p99/p99.9 中位数均为 0/42/42 ns。虽然其他任务暂停了密集计算，primary 基线仍出现 37.0 ms 的单次最大值，sparse 候选出现 24.3 ms；这些原值保存在 CSV。当前保留此实现，是因为目标散布负载的收益稳定、相邻与最佳价插删没有出现先前的系统性退化，并保持了已有结构更新收益。

这轮性能样本全部成功应用，且每次只处理单个热缓存实例。快照安装、非法输入拒绝耗时、多标的轮转、真实录包和目标 Linux 主机延迟尚未测量；快照安装仍为原有最坏 `O(N²)`。本轮没有新增 book generation 的 TLA+ 模型，状态与策略安全性由已有功能、差分和零分配回归覆盖。[证据清单](SHA256SUMS)固定本轮文件摘要，[数据核验](validation.json)记录行数、分组与源码一致性。
