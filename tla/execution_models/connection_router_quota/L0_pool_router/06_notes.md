# Review notes

1. **Dual-epoch bump on disconnect and reconnect**: `OrderRouter::on_disconnect` (`crates/tickwire-transport/src/order_router.rs:328-337`) and `OrderRouter::on_connected` (`crates/tickwire-transport/src/order_router.rs:308-325`) both advance `route.epoch` and reset `RouteHealth` (`inflight = 0, ema_us = 0, ema_samples = 0`). Any late `release_inflight(conn_id, old_epoch)` or `note_sample(conn_id, old_epoch, ...)` after disconnect or reconnect returns `Ok(false)` without mutating the new connection's `inflight` or EWMA score.
2. **Three-part `poll_pool_dials_filtered` invariant**: Installing a ready `DialBaton` link onto `conn_id` requires simultaneously (a) `pending_send.is_none()`, (b) `retained_receive.is_empty()` (`crates/tickwire-account-gateway/src/pool.rs:310-316`), and (c) owner `slot.pending.is_none()` (`crates/tickwire-binance-account/src/rest.rs:235-270`, `crates/tickwire-spot-execution/src/session.rs:263-289`). Omitting (b) drops unread pre-EOF `200 OK` bytes; omitting (c) aliases a stale `SlotPending` onto the new socket epoch.
3. **Single-point inflight release on `SendState::NoBytes`**: `AccountGateway::apply_slot_report` (`crates/tickwire-account-gateway/src/pool.rs:666-680`) already calls `release_inflight(conn_id, epoch)` when aborting a zero-byte `NoBytes` send, so upper owners (`RestOwner`, `RestSession`, `WsOwner`) must reap `Status::Aborted` entries before reading socket bytes and must not release `inflight` a second time.
