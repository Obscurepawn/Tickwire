# Modeling plan — `L1_MultiIpQuota`

## Scope and state owners
- **`RateLimiter` (`FixedWindow` + `RollingWindow`)** (`crates/tickwire-quota/src/rate_limiter.rs:551-842`, `1117-1460`): owns fixed-epoch rollover (`now / interval`), bounded-ring sliding expiration (`now - ts >= interval`), same-timestamp burst coalescing (`tail.ts == now`), duplicate-`RateLimitId` `prior_units` tracking in `can_afford`, reverse-order `put_back` undo stack in `allow` (`WindowUndo::Fixed`, `RollingCoalesced`, `RollingPushed`), conservative `reconcile_exchange_usage` floor bumps and `80%` warnings, per-IP `IpCooldown`, and account-wide `Frozen` latch.
- **`VenueRateLimiter` & `MultiIpCommandQuota`** (`crates/tickwire-quota/src/rate_limiter.rs:1921-2268`, `crates/tickwire-binance-quota/src/lib.rs:1525-1655`): map `Place` (`[AcctOrder, IpWeight(ip)]`), `Cancel` (`[SymCancel, IpWeight(ip)]`), and `Query` (`[IpWeight(ip)]`) onto disjoint action-class windows so `ORDER` exhaustion never blocks `Cancel` or `Query`.
- **Pre-admission quota discipline & multi-IP failover** (`crates/tickwire-account-gateway/src/pool.rs:420-480`, `crates/tickwire-spot-execution/src/session.rs:1103-1196`): filter pooled routes away from `429`-cooled IPs onto healthy sibling IPs and commit mutating `allow_*` debits only after local order admission succeeds.

## Configurations and invariants
1. **`L1_MultiIpQuota.cfg` (Multi-IP routing failover, `429` vs. `418`, class isolation, & exchange header reconciliation)**: `Ips = {1, 2}`, `AcctOrderCap = 1`, `SymCancelCap = 1`, `IpWeightCap = 3`, `RingCap = 2`, `FixedInterval = 1`, `RollingInterval = 2`, `CooldownTicks = 1`, `MaxClock = 2`, `ReportedSet = {2}`, `AllowAccountBan = TRUE`.
2. **`L1_MultiIpQuota_rolling_coalesce.cfg` (Tight rolling ring saturation, duplicate `RateLimitId` spends, & multi-window `put_back` rollback)**: `Ips = {1}`, `AcctOrderCap = 2`, `SymCancelCap = 1`, `IpWeightCap = 4`, `RingCap = 2`, `FixedInterval = 2`, `RollingInterval = 3`, `CooldownTicks = 1`, `MaxClock = 2`, `ReportedSet = {4}`, `AllowAccountBan = FALSE`. Forces `Len(entries) == RingCap` while `used < IpWeightCap`, verifying same-timestamp coalescing vs. ring-full `Exhausted`, duplicate `RateLimitId` `prior_units` agreement, and both `RollingCoalesced` and `RollingPushed` `put_back` rollbacks.
3. **Invariants**: `TypeOK`, `WindowCapsRespected`, `TransactionalRollbackExact`, `CanAffordMatchesAllow`, `CancelAndQueryIsolatedFromOrderCap`, `PerIpCooldownIsolation`.
