# Multi-connection order router, multiplexed WebSocket pool, and multi-IP venue quota

Iteration 3 scales outbound order execution across `1..=16` concurrent TCP/TLS/WebSocket slots (`OrderRouter` + `OrderConnectionPool` + `AccountGateway` pool) and enforces preallocated fixed- and sliding-window exchange rate limits across account, symbol, and multiple local source IPs (`RateLimiter` + `VenueRateLimiter` + `MultiIpCommandQuota`). `L0_pool_router` verifies `SendSlot::Exclusive` (`inflight <= 1`) and `SendSlot::Shared` (`inflight <= MaxShared`) concurrency bounds, integer EWMA (`(ema_us * 7 + sample_us) / 8`) warmup round-robin and `9/8` sticky hysteresis, epoch-fenced inflight release, pre-EOF `retained_receive` / `Runtime.draining_eof` response draining before `DialBaton` reconnect installation, and zero-byte `Aborted` vs. ambiguous post-byte `InDoubt` isolation; `L1_multi_ip_quota` verifies `FixedWindow` and coalescing `RollingWindow` caps, stack-based `put_back` transactional rollback, `can_afford` vs. `allow` equivalence across duplicate `RateLimitId` spends and ring saturation, pre-admission local rejection non-burn, `Order` vs. `Cancel` vs. `Request` class isolation, per-IP HTTP `429` failover, and account-wide HTTP `418` freeze.
