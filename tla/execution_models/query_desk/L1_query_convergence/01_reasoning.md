# Coalescing, slot-generation tickets, and two-step Bybit convergence

`QueryDesk` decouples logical per-order reconciliation intent (`asks: WindowedTable<OrderKey, StatusAsk>`) from physical concurrency (`slots: Box<[SlotState]>`). Waiting asks occupy zero REST slots during `status_query_delay_ns`, `place_retry_ns`, or exponential cancel backoff. When `poll_due` claims a free `QueryDesk` slot `s`, it mints a monotonically increasing `(slot, generation)` `QueryTicket`. Both `PerOrderQueryDriver` implementations enforce `self.in_flight[s].is_none()` before claiming `s`, preventing wire-slot aliasing when a concurrent WebSocket terminal push calls `QueryDesk::remove_order` (`desk_slot_order[s] := 0`) while `"tw-rest-query"` has not yet delivered the in-flight HTTP reply for `s` (`wire_active[s] == TRUE`). When that stale reply eventually arrives, `claim_ticket` (and `is_ticket_in_flight` prior to chaining Bybit `/v5/order/history`) rejects the mismatched generation (`DiscardStaleWireReply`).

Coalescing on a single `OrderKey` maintains two orthogonal deferred latches—`cancel_after` and `trades_after`—alongside `known_terminal`:

1. **`Trades` priority without losing `Cancel` (`CancelAfterNeverLost` & `TradesBeforeFeeClosure`)**: If a lagging WebSocket `orders` push (`cum > local_filled`) arrives while `OrderStatus` (`Place` or `Cancel`) is in flight, `enqueue_ask(AskKind::Trades)` sets `trades_after = true` without dropping a pending non-terminal cancel. Conversely, if an ambiguous `Cancel` arrives while `Place`, `Cancel`, or non-terminal `Trades` is waiting or in flight, `QueryDesk` sets `cancel_after = true` (or upgrades waiting `Place` to `Cancel`). Across every completion path that leaves the order non-terminal—`on_not_sent`, `on_transport_failure`, pre-grace `on_not_found`, `on_status_snapshot`, `on_trades_applied`, and `poll_due` skipping an already caught-up `Trades` ask—`trades_after` promotes first to `AskKind::Trades` (preserving `cancel_after`) and `cancel_after` promotes next to `AskKind::Cancel`.
2. **Zero-byte vs. counted-write budget separation (`IssuedOnlyCountsSent` & `BoundedEscalationToFreeze`)**: Local pre-enqueue refusals (SPSC ring full, rate-budget denial) and `AsyncRestQuerier` zero-byte completions (`RestStatus::NotBuilt`, `RestStatus::Expired`) invoke `QueryDesk::on_not_sent`, freeing the slot and promoting deferred flags without touching `issued_query_count` or `cancel_calls`. Only replies where bytes were sent (`on_transport_failure`, pre-grace or confirmed `on_not_found`, and `on_trades_applied(..., false)`) increment `issued_query_count` toward `max_query_count` (`FreezeAccount`), while Category B HTTP hazards (`429`, `418`, `401`/`403`) freeze immediately.
3. **Bybit two-step `realtime -> history` chain (`BybitTwoStepSoundness`)**: Empty `/v5/order/realtime` (`OrderStatusPrimary`) never calls `on_not_found` directly; `dispatch_bybit_history` verifies `is_ticket_in_flight(ticket)` and chains `/v5/order/history` (`BybitOrderStatusHistory`) on the same `(slot, generation)` ticket (or short-circuits to `AskKind::Trades` if an open WS partial fill arrived mid-flight). Only an empty `/v5/order/history` reply invokes `on_not_found`, which requires `clock >= first_doubt + GraceTicks` and `!confirmed` for `CloseUncreated` (isolating `DoubtReason::FillCatchup` + `AskKind::Trades` instead whenever `confirmed == true`).
