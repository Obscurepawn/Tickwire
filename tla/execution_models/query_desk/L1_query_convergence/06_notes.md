# Review notes

1. **`known_terminal` vs. `Account` `terminal` separation**: When `OrderStatus` returns `NotFound` (`-2013`, `51603`, or empty Bybit `realtime` + `history`) on an already-confirmed order (`confirmed == true`), `Account` does not fabricate a synthetic `Canceled` order status event; instead, `QueryDesk::on_not_found` sets `known_terminal = true` and returns `FetchTradesBeforeClose`, while `PerOrderQueryDriver` isolates `DoubtReason::FillCatchup` so `OrderTrades` reconciles all executed fills before clearing doubt.
2. **Stale ticket immunity on Bybit two-step chains**: `PerOrderQueryDriver::dispatch_bybit_history` (`crates/tickwire-spot-runner/src/query_desk_driver.rs:517-552`) checks `QueryDesk::is_ticket_in_flight(ticket)` before dispatching `/v5/order/history`, ensuring that a private WebSocket terminal push arriving while `/v5/order/realtime` was in flight neither leaks a history query nor resurrects a closed ask.
3. **Out-of-order REST vs. WebSocket monotonicity**: Private WebSocket `orders` pushes and asynchronous `AsyncRestQuerier` `OrderStatus` snapshots race independently on the wire. Taking `effective_cum_atoms = max(remote_cum, local_filled, expected_fill)` and treating older open REST snapshots as `Applied::Duplicate` prevents false `FreezeAccount` triggers without masking genuine fill-catchup obligations.
