# Modeling plan and abstraction reasoning — `L0_SharedOrsLimiter`

## Scope and state owners
- **`SharedRateLimiter` (`AtomicFixedWindow` + `AtomicRollingWindow`)** (`crates/tickwire-quota/src/shared.rs:312-643`, `1251-1441`): owns lock-free packed `(epoch, used)` fixed windows, 20-sub-bucket sliding rolling windows (`in_window_sum` + `(sub_tick, count)` slots), per-account (`AccountCooldownSlot`) and per-IP (`IpCooldownSlot`) cooldown/freeze tables, reverse-order `put_back_undo` stack unwinding (`SharedUndo::{Fixed, Rolling}`), `pick_and_spend_or_nack` single-pick enforcement, and exact integer `reconcile_venue_usage` (`u128` `80%` / `100%` rising-edge hysteresis latches).
- **`OrsAccountQuota` & `AccountSession` single-pick route admission** (`crates/tickwire-quota/src/shared.rs:1580-1816`, `crates/tickwire-transport/src/order_router.rs:688-745`, `crates/tickwire-runtime/src/session.rs:518-580`, `crates/tickwire-spot-execution/src/session.rs:1185-1233`): maps `Place` (`[AcctOrder(a), SharedIp(local_ip)]`), `Cancel` (`[AcctCancel(a), SharedIp(local_ip)]`), and `Query` (`[AcctReq(a), SharedIp(local_ip)]`) across `Accounts = {1, 2}` sharing `RateRule::ip` (`account = 0`), while `PublishedRoutes::pick` chooses at most one ready connection without sibling failover on rate-limit NACK.
