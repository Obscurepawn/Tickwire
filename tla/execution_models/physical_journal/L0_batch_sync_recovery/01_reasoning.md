# L0 建模依据

本层使用 faithful fault injection：完整批可能在 write_all 中短写、在 sync_data 前后崩溃，或同步返回错误。源码在每种 I/O 错误后关闭 writer；只有重新验证和同步后的新实例可以继续。每个调用由 `&mut self` 独占，文件锁覆盖多个进程，没有两个 writer 并发追加。

## 内容与完成边界

`s.cache` 是当前文件可读内容；`s.disk` 是同步已完成或故障后存活的内容边界。二者包含有序 frame token，token 保留批号、执行代次、不同调用的 payload 身份和在批内的位置。一个 token 代表 Begin、DataRecord 或 Seal；primary 每批一条记录，batch 配置两条记录。帧内撕裂归入最后一个 token 未完成，保留相同恢复决策；完整 CRC/SHA 损坏由 `badAt` 的真实位置见证，恢复拒绝，不把校验位当成未封口。

`WriteFrame` 把 write_all 拆到各帧边界；`SyncSuccess` 在完整 seal 后推进同步内容；`ReturnReceipt` 单独一步发布收据。把同步成功与收据返回拆开能检查回执丢失。只从同步内容检查收据安全会遗漏实际顺序错误，所以额外保留历史完成同步集合 `synced`，每张收据必须匹配其中的完整内容。

普通 Crash 保留已经同步的全部字节，并从未同步后缀保留任意前缀。恢复截断后、再次同步前崩溃，旧未封口尾部可以重现，也可以保持缩短。同步失败不强制写入消失。Linux SIGKILL 实测只涵盖进程退出与页缓存仍存活；TLC 的撕裂前缀是设计故障模型，不能充当设备掉电验收。

## 恢复与信任边界

恢复首先保存读取内容 `checked`，检查内容连续性、完整帧损坏位置和可选的外部收据前缀。验证失败进入 Quarantine，不修改文件。验证成功只保留完整批次，并完成恢复同步后才返回 Ready。恢复同步报错没有返回可用 Journal，模型用禁用追加的 Poisoned 表示该失败。

外部可信前缀由 caller 选择；模型同时探索给定最后一张收据和不提供收据。`LoseWholeTail` 是成功同步假设以外的诊断故障，删除实际 token 内容而非只改水位。有可信前缀时进入隔离；没有前缀时接受较短完整历史符合现有 API，`NoAcknowledgedLossUnderSupportedCrash` 因而明确只约束没有媒体丢失的执行。检查无前缀无法检出完整尾部丢失，不是预设该故障安全。

## 有限范围

16 个动作均映射到当前源码。每个配置限定调用数、崩溃数和每批记录数，执行代次取 1/2；一次离线媒体故障可以是完整帧损坏或完整尾丢失。恒定 domain/stream、一个 segment、无计数器溢出。Rust 另测真实字节布局、所有单 bit 错误、每个截断位置、有效 checksum 下的序号/epoch/identity 错误、分段/manifest/锁。模型不执行 SHA/CRC，不证明密码学抗碰撞、目录事务、跨进程文件锁实现、任意重排损坏或完整交易系统。
