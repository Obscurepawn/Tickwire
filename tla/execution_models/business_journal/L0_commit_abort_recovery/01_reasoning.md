# L0 抽象依据

`disk` 是完成同步的业务事件序列，`cache` 是可读的完整批前缀。单写、失败后冻结使两者最多相差一个事件。追加错误可以留下该完整事件，也可以只留下未封口片段；后者恢复丢弃，因此在本层等价于没有追加该事件。物理帧内 CRC/hash、segment/manifest、bootstrap 解析不在本层重复展开。

`closure` 按意图保存授权服务已返回的持久闭包。成功授权动作只在闭包持久化后返回，失败动作冻结 runtime。这个集合是下层受信服务契约的抽象，内部内容与签名不由本层证明。恢复查询已有集合，查询失败可以停止恢复，绝不补造闭包。

`live` 表示当前门允许该批意图，包括租约、期限、writer epoch、策略代次和配置版本。`GateExpire` 可在授权/物理 I/O 等待时把它关闭；发送动作使用等待后采样的当前值。最后一次采样、纯内存 accept_commit/begin_send 和同步调用 Exchange 的连续代码合成一个动作，不建模任意 CPU 指令间的时间推进，也不声称网卡实际发包时仍满足期限。

`held`、`prepared` 和 `aborted` 是 reducer 在该受限事件集合中的状态；`called`、`noBytes`、`released` 是历史见证。发生崩溃后，运行时内存清空，恢复从第一条日志按顺序重放并始终冻结。新进程不能因恢复完成而重发。NoBytes 回调之后、Aborted 同步之前崩溃，会恢复 Prepared 并保留预留；Aborted 完整存活并经恢复同步后，才允许释放。

本层不展开独立的幂等 API：runtime 一次完成发送后拒绝重试，失败后冻结。业务 Journal 跨 writer 幂等位置由 Rust 回归验证，L2 再展开。恢复故障采用 verify 调用失败出口，不注入永久闭包无故丢失。
