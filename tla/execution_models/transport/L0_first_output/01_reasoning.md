# State and Abstraction

A `Connection` owns at most one active `SendSlot` at a time, and all state transitions run through exclusive `&mut self` calls. The environment may toggle the admission gate (`ToggleGate`) and advance monotonic time (`Tick`) between calls. First-output authorization and the initial byte acceptance happen inside a single atomic `FirstAccept` transition; no cross-call authorization token is cached. If the synchronous `authorize()` closure itself crosses the send deadline, `ExpireInGate` models the second `self.expire(now.max(Instant::now()))` check (`crates/tickwire-transport/src/connection.rs:396-399`) that rejects the slot as `NoBytes` before touching the TLS or socket writer.

`accepted[i]` tracks the plaintext application bytes handed to `rustls::Writer` or the plain TCP socket for send `i`. `wire[i]` witnesses the prefix flushed into the local kernel socket — it represents local transmission progress, never remote peer receipt or venue order acknowledgement. `buffered` models accepted TLS plaintext whose ciphertext records have not yet been flushed by `write_tls`, while `tlsBlocked` models `set_buffer_limit` backpressure from un-drained TLS handshake or control records. Under TLS configurations, the model independently reaches zero acceptance, buffered plaintext with zero socket output, partial socket flush, and full `Flushed` completion; under plain TCP (`TLS = FALSE`), socket writes advance `accepted` and `wire` together.

Capacities are expressed in abstract application-byte units rather than exact TLS record headers or AEAD tag bytes. `TryZero` merges `Ok(0)`, `WouldBlock`, and `Interrupted` into a state-preserving retry boundary so subsequent `try_send` calls re-evaluate expiry and (when `accepted == 0`) the synchronous authorization gate.

Monotonic time takes bounded integer ticks (`0..MaxTime`), and each queued frame chooses an independent deadline. `ExpireQueued` and `ExpireAccepted` model deadline detection at the entry of `drive` or `try_send`: zero-accepted expiry (`ExpireQueued`) yields `NoBytes` while keeping the live connection reusable, whereas partial-accepted expiry (`ExpireAccepted`) closes the connection and records `Failed`. Taking a `NoBytes` or `Flushed` report clears `current` so subsequent sends can reuse a healthy connection without resurrecting prior `NoBytes` slots.

Connection establishment abstracts nonblocking TCP `Connecting`, TLS `Handshake`, and `Ready`. Handshake or I/O errors collapse into `FailConnection`, closing the socket without manufacturing spurious output. Inbound HTTP/WS/FIX framing is orthogonal to single-slot outbound first-output accounting and is verified alongside multi-thread `REQ`/`RESP` lock discipline in [L1_sym_dual_thread_switchover](../L1_sym_dual_thread_switchover/05_output.md).
