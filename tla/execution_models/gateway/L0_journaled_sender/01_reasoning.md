# 状态与抽象

一个连接最多持有一个待发槽；前一项已完整冲刷、等待业务回包后，协调器允许下一项进入槽位。模型使用二至三个意图，分别保留每个意图的已接受前缀、已冲刷前缀和入队次数。因此旧意图的 Unknown 或 Aborted 不能被新槽位掩盖。

`status` 对应协调器的 entries，`pending` 对应唯一待发意图。`accepted` 表示应用明文已经交给 TLS writer 的前缀，`wire` 表示该前缀已冲刷到本机 socket；两者都不表示交易所 ACK。`durableIntent` 和 `durableAbort` 表示恢复能够验证的完整 WAL 记录，`closure` 表示同步闭包已验证；这些是数据见证，不是仅供显示的标签。

模型将 `submit` 分成闭包完成、意图 WAL 同步、队列建立；将零接受中止分成 WAL 同步和发布 Aborted。其间只允许时间推进或进程崩溃，其他公开变更方法只能在调用边界进入。`poll` 同样按 drive、读取终态、尝试应用写入、返回分阶段，避免在内部步之间插入源码不允许的 cancel 或新 submit。

WAL 的成功同步使对应记录持久；返回错误或进程在同步期间崩溃时，完整尾记录可以存活或丢失。损坏尾帧、缺少闭包或身份冲突统一进入恢复失败，绝不构造可发送实例。只要恢复成功，实例没有网络连接，所有未持久中止的意图恢复为 Unknown，并保持冻结。文件系统写入、批帧、manifest 和目录同步的内部阶段由物理 WAL 模型及实际文件故障测试覆盖。

`gate` 表示完整 `permits` 合取条件：enabled、market_valid、account_valid、recovered、owner_isolated、有效租约、命令截止、writer/intent epoch、策略代次和配置版本。它可在每次调用前变化，首次应用接受动作现场检查它；零接受的 WouldBlock 不保存许可，下一次尝试重新检查。transport 在同步授权闭包之后重读 Instant 的截止检查另列动作。首次接受后继续同一报文不重新批准，也不再产生 NoBytes。

报文字节以小整数前缀计数；TLS 记录头、加密开销和精确缓冲容量不影响所检查的顺序。未就绪、零接受阻塞、短写、接受后断连和冲刷后 EOF 均保留独立分支。模型使用有限期限状态，检查调用时观察到的期限，未证明网卡输出截止或无条件活性。

规范命令身份、路由和摘要取“匹配/不匹配”的等价类。精确重复返回原状态，内容冲突冻结实例；任意新意图在冻结后都被拒绝。实际字节编码、哈希碰撞、风险数值预算与资金释放算法不在本级范围；Aborted 只作为上层可消费的持久中止结果。

首次 writer.write 直接出错但尚未接受任何字节时，transport 关闭连接并给出 NoBytes。协调器先同步中止；该次 poll 先前的 drive 仍可为成功，因此实例在返回时尚未冻结。下一次 poll 观察关闭连接后冻结；若调用者先提交另一意图，它会先同步 WAL，再在 queue 的关闭连接检查处失败，冻结并同步中止。模型保留这个顺序。私有发送槽已经全部接受时，try_send 提前返回而不再调用 writer.write；TryBlocked 在该状态表示此早返回。

每个有限意图固定规范命令、writer epoch、唯一路由及互异的 intent sequence。错误身份和编码/授权失败归为提交前拒绝；精确重复与冲突分别建模。发送 ID 的 u64 耗尽、数值风险预算、恢复时的成交/费用事实及其语义冲突不属于本级有限域。QueueFail 配置实际通过已关闭的 socket 触达，没有把发送 ID 上限缩小来制造失败。

源码在 SettleFailed 后仍可能对已终态的槽位调用一次 try_send，再次得到同一 Failed；它不写网络，模型直接进入 EndPoll。模型内的初次授权见证只记录同步门禁采样与 transport 截止检查，Aborted 只记录可交给账户的持久中止状态。资金 reducer 的实际释放另由风险/执行层验证。

零 IoBudget 属于独立输入错误：transport 在检查期限和操作 socket 前直接返回 Bounds，保持连接与发送报告；协调器随后将尚未中止的意图冻结为 Unknown。DriveBudgetError 保留这一分支，只有真实网络/连接故障使用 DriveFailure 的关闭语义。
