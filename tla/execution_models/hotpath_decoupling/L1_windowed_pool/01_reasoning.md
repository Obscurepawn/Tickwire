# Stateless active-protected retention, associative fill-pool dedup, and management headroom

`Account` and `AccountGateway` bound resident state purely in memory using active-protected monotonic retention windows (`now_mono_ns >= retired_at + Window`) with zero local WAL or journal state. An order in `Account` becomes retirable (`Order::is_retirable` / `Account::is_order_retirable`) only when `!unknown`, `in_doubt.is_none()`, no amendment or modification targeting the order is in flight (`!aborted && !confirmed && rejected.is_none()`), and either `aborted` holds or `terminal && remaining() == 0` (`terminal_cumulative == Some(filled)`). After retirement, `Account::evict_expired` retains the order, its `IntentKey` admission, and all associated `FactKey` entries until both `retired_mono_ns + Window <= now` and `facts_for_order_expired` hold, while `AccountGateway::evict_retired_entries` guards `!self.account.has_admission(*key)` and derives `completed_mono_ns` from `max(last_mono_ns, evaluated_at, intent_retired_mono_ns)` so gateway and reducer entries age out in lockstep.

Individual trade executions pass through `FillRecordPool::record_or_amend` (`2^fill_map_exponent` associative buckets of `FILL_BUCKET_WAYS = 8` ways keyed by `(ors_order_id, exec_ref, side, symbol_id)`) alongside `Account.facts`:
- First execution (`TRADE_LITE` with `fee == None` or full `TRADE` with `fee == Some(...)`) claims an empty way or overwrites the oldest expired way (`now_mono_ns - recorded_mono_ns >= retention_ns`), returning `FillRecordOutcome::Applied` and booking filled quantity once.
- Duplicate `TRADE_LITE` or identical-fee replays across the order socket and private user stream return `FillRecordOutcome::Duplicate` with zero quantity or fee mutation.
- Post-trade fee upgrades (`TRADE` arriving after `TRADE_LITE`) or fee/rebate revisions return `FillRecordOutcome::Amended` (`amendment = true`): `Account` reverses `previous_fee`, applies `new_fee` (`reported_fee_delta = new_fee - previous_fee`) strictly to wallet balances without re-booking filled quantity, refreshes `recorded_mono_ns`, and extends `intent_retired_mono_ns`.

Order-creating admissions (`New`) are capped at `MaxOrders`, whereas non-increasing management commands (`Cancel`, `Query`) draw from an independent `MaxMgmt` (`MAX_MANAGEMENT_ADMISSIONS`) pool. While queued on the outbound wire (`pending_send != 0`), `AccountGateway` clears `retired_mono_ns` (`set_management_retired(key, None)`) so an in-flight management frame cannot be reclaimed mid-send. If a socket drops after `accepted_bytes > 0` (`per_order_doubt_isolation`), `drop_broken_transport_isolated` marks only the affected order `in_doubt` (`Status::Unknown`) without halting sibling orders, blocking eviction until an authoritative venue status or fill arrives. Once a management frame flushes or aborts, `reclaim_one_retired_management_entry` atomically evicts the oldest retired management `IntentKey` across both `AccountGateway` and `Account` whenever `MaxMgmt` is full—even if all `MaxOrders` slots hold live resting orders.

Ghost specification observers (`ghost_orders`, `ghost_retire_at`, `admit_count`, `fact_first_at`, `fact_last_at`, `trade_book_count`, `ghost_expected_fee`) are never read by live eviction logic: `RetryDuplicateIntent` and `DuplicateTradeFill` probe the live tables (`gw_status`, `acct_adm`, `fill_ways`, and `facts`) and increment `admit_count` or `trade_book_count` if an in-window key were ever absent, making `ActiveNeverEvicted`, `WindowDedupPreserved`, `FillAmendmentExactness`, and `ManagementNeverStarved` non-tautological.
