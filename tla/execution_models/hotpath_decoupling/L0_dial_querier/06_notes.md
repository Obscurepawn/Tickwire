# Review notes

1. **`IpPool` last-peer preservation**: `IpPool::note_syn(addr, None)` (`crates/tickwire-transport/src/dialer.rs:103-124`) marks `last_failed = true` and removes the entry only when `in_use == 0 && peers.len() > 1`, ensuring `take_ip()` retains a fallback endpoint under transient network partitions.
2. **Stalled-consumer reply safety**: `AsyncRestQuerier::enqueue` bounds `task_queue` to `Capacity`, while `run_query_worker` (`crates/tickwire-transport/src/rest_querier.rs:774-786`) bounds `waiting.len() + usize::from(inflight.is_some()) + shared.reply_queue.len() <= Capacity` independently. Worst-case live tasks across the channel equal `2 * Capacity` (`Capacity` in `task_queue` plus `Capacity` split across `waiting`, `inflight`, and `reply_queue`), and `post_reply` (`crates/tickwire-transport/src/rest_querier.rs:677-681`) never fails even if `ConsumerDequeue` never runs.
3. **Zero-byte failure accounting**: `RestStatus::Expired` and `RestStatus::NotBuilt` are reachable only with `query_count == 0`; once `sync_counted_send` (`crates/tickwire-transport/src/rest_querier.rs:1218-1227`) observes `accepted_bytes > 0` or `SendState::Flushed`, subsequent deadline expiry surfaces the last concrete `HttpError` (`5xx`) or transport status (`SendFail`, `ReadFail`, `Timeout`) alongside the exact counted write count.
