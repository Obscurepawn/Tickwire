# Independent review of BBO subscription loss

Reviewed against Tickwire `9b2ed630721911e01046822bddc9db21b2fa5aee`. The observed failure is permanent quarantine of the subscription object after an ordinary unavailable notification. The local execution gate correctly refuses trades from the invalidated generation.

**Reconstruction.** The publisher can receive an unavailable event after it has already published an exact quote. It then publishes two well-formed records on the same ring, stale feed state followed by stale exact quote. The receiver applies each record and reports each discontinuous view to its sink. Its trigger uses the applied ring sequence. The second record therefore has a different sequence, even if its timestamp equals the first record's timestamp. See `crates/tickwire-market-publisher/src/spot.rs:58-76`, `crates/tickwire-market-publisher/src/spot.rs:129-141`, `crates/tickwire-market-source/src/replica.rs:165-174`, `crates/tickwire-market-source/src/replica.rs:237-249` and `crates/tickwire-market-source/src/shm.rs:293-306`.

**Refutation attempts.** The runtime policy's same-sequence fast path cannot accept the second record. The first observation already invalidated that generation, and a new sequence on that generation returns `Stale`. Polling the two records in one budget still calls the sink twice. The simple local observer converts the policy error into a sink rejection. The SHM source stops, the enclosing app sets its member's `failed` bit, and subsequent polls skip that member. See `crates/tickwire-runtime-policy/src/lib.rs:639-665`, `crates/tickwire-runtime-policy/src/lib.rs:1051-1075`, `crates/tickwire-market-source/src/shm.rs:330-344`, `crates/tickwire-app/src/market.rs:205-245` and `crates/tickwire-spot-runner/src/live.rs:44-51`.

**Recovery boundary.** An invalid generation is expected to stay closed. The policy explicitly accepts a higher feed or ring generation. The app offers an approved in-process transition, but both `validate_arm` and `arm` look up a member that must still have `failed == false`. Consequently a later valid approval cannot reach this object, before it even checks the approval or joins the new bank. The generic app has a real caller of this API. The spot live executable constructs its source group at startup and has no replacement path in the live loop. Constructing a new process/group lies outside this witness. See `crates/tickwire-runtime-policy/src/lib.rs:624-634`, `crates/tickwire-app/src/market.rs:93-115`, `crates/tickwire-app/src/market.rs:135-160`, `crates/tickwire-app/src/control/market.rs:189-212` and `crates/tickwire-spot-runner/src/live.rs:109-119`.

**Disposition.** Confirmed availability defect. A valid producer notification can retire the execution subscription and exclude an approved replacement. No unsafe order write is demonstrated. A regression should retain the member through both stale records, continue to reject old-generation market triggers and admit an explicitly approved new generation.
