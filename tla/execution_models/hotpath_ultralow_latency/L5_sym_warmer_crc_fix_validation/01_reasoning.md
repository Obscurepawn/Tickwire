# Modeling reasoning — `L5_SymWarmerCrcFixValidation` (`/vibe-tla fix` validation)

## 1. Closed findings from `L3_SymRingWarmerInductive` and `L4_SymSimdCrcBmc`

1. **Fix 1 (`CoreNode::step_inner` non-zero `mio::Poll` sleep when unready, frozen, halted, or on warmup error — `crates/tickwire-runtime/src/node.rs:430-452, 826-845, 894-905`)**:
   - Pre-fix `L3` Z3 witness (`diag_corenode_spin_witness.tla`) proved that when `!node_ready` (`account.frozen() || gateway.halted() || !rest.submission_ready()`) or when `maybe_warm_hot_path_with_account` returned `Err(_)`, `step_inner` left `last_activity_ns` and `last_warm_ns` un-advanced while clamping `next_deadline` to `next_warmup_due_ns() <= now_mono_ns`, causing `run_with` to pass `Duration::from_nanos(0)` to `mio::Poll` on every quiescent iteration.
   - Post-fix `step_inner` routes the idle branch through `self.maybe_warm_hot_path(now_mono_ns)` (which calls `self.session.record_activity(now_mono_ns)` when `frozen() || halted() || !submission_ready()`), also calls `self.session.record_activity(now_mono_ns)` when `self.maybe_warm_hot_path(now_mono_ns).is_err()`, and clamps `next_deadline` to `self.session.next_warmup_due_ns()` **strictly** when `!frozen() && !halted() && submission_ready()`.
2. **Fix 2 (`WarmupTracker::next_due_ns` `checked_add` parity with `can_warm` across `0 .. 2^64 - 1` — `crates/tickwire-transport/src/warmup.rs:152-177`)**:
   - Pre-fix `L3` Z3 witness (`diag_u64max_next_due_witness.tla`) proved that `saturating_add` returned `Some(u64::MAX)` whenever `anchor + warmup_interval_ns > u64::MAX`, whereas `can_warm(u64::MAX)` evaluated `(u64::MAX - anchor) >= warmup_interval_ns == false` (which would also cause a `0ns` deadline wait at `now == u64::MAX`).
   - Post-fix `next_due_ns` returns `anchor.checked_add(self.config.warmup_interval_ns)`, establishing an exact algebraic biconditional `can_warm(t) <=> next_due_ns().is_some_and(|due| t >= due)` across all `(anchor, warmup_interval_ns, t) \in [0 .. 2^64 - 1]^3`.
3. **Fix 3 (Cold-startup `CLOCK_MONOTONIC` seeding when enabling warmup — `crates/tickwire-runtime/src/node.rs:848-874`, `crates/tickwire-binance-execution/src/lib.rs:695-717`, `crates/tickwire-spot-runner/src/live.rs:364-374`)**:
   - Pre-fix `L3` Z3 witness (`diag_startup_anchor0_witness.tla`) proved that enabling warmup on a cold session with `last_activity_ns == 0 && last_warm_ns == 0` fired `warm_once` at `0ns` of session idle time whenever `startup_clock_ns >= warmup_interval_ns`.
   - Post-fix clock-owning entrypoints (`CoreNode::set_warmup_interval_ns`, `SharedSessionState::set_warmup_interval_ns`, and `spot-runner` `live::run`) sample `CLOCK_MONOTONIC` when `warmup_interval_ns > 0 && last_activity_ns == 0 && last_warm_ns == 0` and seed `record_activity(startup_clock_ns)`, guaranteeing `warm_count > 0 => now_ns - startup_clock_ns >= warmup_interval_ns`.
4. **Fix 4 (`tickwire_journal::crc32c::crc32c_masked` total clamping parity with `tickwire_ipc::crc32c_masked` — `crates/tickwire-journal/src/crc32c.rs:180-195`, `crates/tickwire-ipc/src/crc32c.rs:152-168`)**:
   - Pre-fix `L4` Z3 witness (`diag_journal_crc_range_witness.tla`) showed `tickwire_journal::crc32c::crc32c_masked` panicked via `assert!` on inverted (`start > end`) or out-of-bounds (`end > len`) ranges, whereas `tickwire_ipc::crc32c_masked` clamped gracefully.
   - Post-fix `tickwire_journal::crc32c::crc32c_masked` computes `let end = zero_range.end.min(input.len()); let start = zero_range.start.min(end);`. Note a subtle structural distinction on inverted ranges (`mask_start > mask_end` inside `0..buf_len`, e.g. `7..3` on `buf_len = 10`): `journal` clamps to empty range `3..3` while `ipc` clamps to empty range `7..7`. Because Castagnoli CRC-32C `update` is associative over byte concatenation (`buf[..3] || buf[3..10] == buf[..7] || buf[7..10] == buf[..10]`), `L5` proves **both** structural validity (`0 <= start <= end <= buf_len` and equal zero-run length `end - start`) **and** universal per-byte effective stream equivalence (`JournalByteZeroed <=> IpcByteZeroed`) for a symbolic byte index `probe_idx \in 0 .. buf_len - 1` across `0 <= buf_len <= 2^64 - 1` (subsuming `0 .. 1048576`) and `0 <= mask_start, mask_end <= 2^64 - 1`.
