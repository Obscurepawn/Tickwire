# Symbolic 64-bit/128-bit audit notes — `L4_SymSimdCrcBmc`

1. **Exactness of `simd_json` 20-byte length cap & `u128` overflow fallback (`crates/tickwire-md/src/spot_quotes/simd_json.rs:528-621` vs `crates/tickwire-binance/src/decimal.rs:34-94` & `feed.rs:384-419`)**:
   - `parse_positive_units` rejects `raw.len() > 20` upfront (`simd_json.rs:528`), whereas `Decimal::parse` checks only `digits > 19` (`decimal.rs:64`). Z3 proves `FastVsOracleExactEquivalence` (`02_models/L4_SymSimdCrcBmc.tla:684-688`) holds with **zero discrepancy** across all byte lengths `0 <= str_len <= 32`: any valid unsigned decimal with `digits <= 19` and `dots <= 1` has `str_len = digits + dots <= 20` (`19` digits + `1` `'.'`), while any `'-'`-prefixed 21-byte input accepted by `Decimal::parse` yields `mantissa <= 0` and is unconditionally rejected by `feed::units` (`if value.mantissa() <= 0 { return None; }`, `feed.rs:387`).
   - Under `step_case = 2` (`step = 5.0000`, `step_mantissa = 50000`, `step_scale = 4`), `mantissa \in [1_844_674_407_370_956 .. 9_999_999_999_999_999_999]` overflows `u64::checked_mul(10_000)` at `simd_json.rs:571` (`None`), delegating to `parse_positive_units_from_parts` (`simd_json.rs:575, 594-621`) which widens to `u128` using the `gcd`-reduced `StepSpec` (`num_mul = 1, den = 5`). Z3 proves exact agreement with `feed::units`'s unreduced `i128` `scaled_val / scaled_step` (`feed.rs:407-418`) across the entire 19-digit domain up to `i64::MAX = 9_223_372_036_854_775_807`.
2. **All-length SIMD/SWAR/scalar bounds & `_mm256_movemask_epi8` sign-extension safety (`crates/tickwire-md/src/spot_quotes/simd_json.rs:281-469, 675-694`)**:
   - Replacing `L2`'s 7 discrete frame lengths `{15, 16, 31, 32, 63, 64, 97}` with symbolic `0 <= frame_len <= 65536` (`MAX_MESSAGE = 16384` at `network.rs:18`) and Mode S2 block-scan induction (`IndInv` at `02_models/L4_SymSimdCrcBmc.tla:726-762`) proves that every 64-byte block chunk (`end = (base + 64).min(bytes.len())`) keeps `last_read_end <= block_end <= frame_len` and `0 <= last_shift_bits < 64`, while `_mm256_movemask_epi8(...) as u32 as u64` (`simd_json.rs:289-291`) prevents negative `i32 -> u64` sign-extension bit corruption when bit 31 is set.
3. **Defensive API contract asymmetry in `crc32c_masked` — `retired: fixed (validated by L5_SymWarmerCrcFixValidation)` (`crates/tickwire-ipc/src/crc32c.rs:154-168` vs `crates/tickwire-journal/src/crc32c.rs:180-195`)**:
   - **Retirement status (2026-11-15)**: Fixed in `crates/tickwire-journal/src/crc32c.rs:180-195` by replacing `assert!` with graceful clamping (`let end = zero_range.end.min(input.len()); let start = zero_range.start.min(end);`), verified by `TotalCrc32cMaskedParity` in `L5_SymWarmerCrcFixValidation` (`Apalache` + `Z3` `IndInv` & `BMC` + `TLC`) and `crates/tickwire-journal/tests/frame.rs`. `L4_SymSimdCrcBmc.tla` retains the pre-fix diagnostic predicate as historical evidence.
   - `pub fn tickwire_ipc::crc32c_masked` clamps arbitrary `Range<usize>` (`start = mask_range.start.min(bytes.len())`, `end = mask_range.end.min(bytes.len()).max(start)`) and hashes exact `buf_len` bytes across all OOB or inverted ranges (`CrcMaskedSlicePartitionExact`).
   - By contrast, `pub fn tickwire_journal::crc32c::crc32c_masked` executes `assert!(zero_range.start <= zero_range.end && zero_range.end <= input.len())`, panicking on inverted/OOB ranges (Z3 witness [diag_journal_crc_range_witness.tla](04_evidence/diag_journal_crc_range_witness.tla): `buf_len = 0, mask_start = 2, mask_end = 1`). All current production journal callers (`crates/tickwire-journal/src/frame.rs:141`) invoke `crc32c_header_masked(&[u8; 136])` (`crc32c.rs:202-237`) rather than `crc32c_masked`, so this is not reachable in production WAL framing; recorded as a public crate API contract asymmetry (`lessons.md` R1.3).
