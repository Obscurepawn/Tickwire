Z3 constructs an unreachable predecessor state (`FirstSeq = 9223372036854775806`, `published_seq = 9223372036854775808`, `cons_read = 9223372036854775808`, `prod_writing = TRUE`, `claim_last = 9223372036854775807`) in which `claim_last < cons_read`, so `ProducerPublishBatch` sets `published_seq' = claim_last < cons_read'`, violating `WatermarkMonotonicOrder'` (`cons_read <= published_seq`). ## 2. Candidate Bugs & 64-Bit Boundary Edge Cases Found by Z3 — Retired: Fixed (`validated by L5_SymWarmerCrcFixValidation`)
- **Retirement status (2026-11-15)**: All 3 findings below are **retired: fixed (validated by `L5_SymWarmerCrcFixValidation`)** via Apalache `0.63.0` + Z3 (`IndInv` $\forall k \ge 0$ in `12.371s`, 64-bit BMC `k=8` in `52.939s`) and TLC (`3,525` / `1,719` distinct states, `16/16` actions covered) alongside native Rust regression tests in `tickwire-app`, `tickwire-transport`, `tickwire-binance-execution`, and `tickwire-spot-runner`. `L3_SymRingWarmerInductive.tla` is preserved as the frozen pre-fix diagnostic witness model.
1. **Candidate Bug 1 (`retired: fixed, validated by L5_SymWarmerCrcFixValidation`) — `CoreNode` `0ns` `mio::Poll` CPU busy-spin when `!node_ready` (`crates/tickwire-runtime/src/node.rs:438-452, 833-846`)**:
   - In `CoreNode::maybe_warm_hot_path` (`node.rs:885-892`), `!node_ready` (`account.frozen() || gateway.halted() || !session.submission_ready()`) explicitly calls `self.session.record_activity(now_mono_ns)` before returning `Ok(false)`.
   - By contrast, `CoreNode::step_inner` (`node.rs:438-452`, invoked inside `CoreNode::run_with` at `node.rs:818`) guards `maybe_warm_hot_path_with_account` behind `if !frozen && !halted && submission_ready` **without** calling `record_activity(now_mono_ns)` in the `else` branch, and then unconditionally clamps `next_deadline` to `self.session.next_warmup_due_ns()` (`node.rs:449-450`). Once `now_mono_ns >= next_warmup_due_ns()` (including immediately on startup when `anchor == 0`), `run_with` (`node.rs:834, 844-846`) computes `wait = deadline.saturating_sub(now) == 0` and polls `mio::Poll` with `Some(Duration::from_nanos(0))`, causing a **100% CPU non-blocking busy-spin** for the entire duration of account freeze, gateway halt, or startup/reconnect recovery (the same `0ns` spin also triggers if `let _ = self.session.maybe_warm_hot_path_with_account(...)` at `node.rs:442` discards `Err(Error::Encoding)` without advancing `last_warm_ns` or `last_activity_ns`).
   - **Z3 Witness** ([diag_corenode_spin_witness.tla](04_evidence/diag_corenode_spin_witness.tla)): `WarmupInterval = 18446744073709551614`, `now_ns = 18446744073709551614`, `last_activity_ns = 0`, `last_warm_ns = 0`, `node_ready = FALSE`, `not_ready_polled = TRUE` $\implies$ `step_wait_ns = 0`.
2. **Candidate Edge Case 2a — Cold-startup unseeded `anchor == 0` immediate warmup fire (`crates/tickwire-transport/src/warmup.rs:88-95, 113-115, 165-176`)**:
   - `WarmupTracker::new` initializes `last_activity_ns: 0, last_warm_ns: 0`, and `set_warmup_interval_ns` leaves both at `0`. When `CLOCK_MONOTONIC >= warmup_interval_ns` at process start, the first quiescent poll evaluates `now_ns.saturating_sub(0) >= interval == true` at `0ns` of actual session idle time. Live business/TLS safety still holds (`!order_in_flight`), but seeding `record_activity(now_ns)` on startup/enablement restores the intended initial idle delay.
