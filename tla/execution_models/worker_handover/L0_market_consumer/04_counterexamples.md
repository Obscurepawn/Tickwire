# A valid worker receipt can stop a hosted strategy

**Confirmed at `9b2ed63`.** The remote strategy host samples monotonic time, then polls up to 16 packets. A worker in a separate process can generate and send a legitimate receipt after that sample. The host consumes the packet and compares its timestamp with the earlier sample. The source validator returns `Identity`. The remote strategy's error handler asks the policy to stop the instance, starts quiescing, attempts to terminate its owned child and retains the error. [Host poll](../../../../crates/tickwire-strategy-host/src/remote.rs#L307) · [Frame receive](../../../../crates/tickwire-strategy-host/src/readiness.rs#L76) · [Timestamp comparison](../../../../crates/tickwire-market-source/src/transition.rs#L207) · [Failure handler](../../../../crates/tickwire-strategy-host/src/remote.rs#L293) · [Runtime entry](../../../../crates/tickwire-strategy-host/src/remote.rs#L356)

1. The host queues ARM and starts its poll at time 0. It can send ARM in that same poll.
2. The shared clock advances. At time 1 the worker creates and sends an ARMED receipt for the approved operation, PID and subscription.
3. The host consumes the reply in the ongoing poll. Its cached time is 0, and the receipt records 1. TLC reaches `HostRejectNewer` in state 7 with both participants alive and the approval still valid. [Raw trace](04_evidence/clock/reject.log)

Run `python3 tla/execution_models/worker_handover/L0_market_consumer/04_evidence/clock/reproduce.py` on Linux with the Rust workspace dependencies available. It builds a temporary copy of the pinned commit, appends a test and prepares an idle dispatcher fixture. Two runs use a real Unix sequenced-packet connection, the project’s authenticated sessions, an immutable receipt object and the production dispatcher. A worker stamp of 1,500,000,001 passes all producer checks. With receiver time 1,500,000,000, the packet is consumed, the host returns `Source(Identity)`, and the receipt slot stays empty. Changing only the receiver sample to 1,500,000,001 produces `Ok(())` and installs the receipt. The test directly exercises the dispatch error. The termination consequence was traced through the caller. [Test source](04_evidence/clock/clock_case.rs) · [Native output](04_evidence/clock/socket.log) · [Independent review](06_review.md)

A repair can sample the receiver clock after a successful receive and use that instant for both session and receipt validation. This preserves rejection of genuinely future-dated receipts and enforces the actual request deadline at receipt. A regression should cover a receipt written between poll entry and receive.
