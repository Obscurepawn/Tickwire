# A valid ARMED receipt can stop its worker

**Confirmed on source revision `9b2ed63`.** A correctly authenticated remote market worker can lose its trading authority during an otherwise healthy Binance topic expansion. An ordinary scheduler preemption between the host’s time sample and packet read suffices. The outcome is scoped to the affected worker instance.

1. The host starts and supervises an independent child. In a valid deployment the host and child share the boot identity, clock generation and Linux time namespace. Both use the host-wide `CLOCK_BOOTTIME` through `tickwire_clock_sys::SystemClock`. Choose three distinct readings `t0 < t1 < t2` well inside all deadlines. [Host launch](../../../../crates/tickwire-strategy-host/src/remote.rs#L50-L69) · [Child creation](../../../../crates/tickwire-strategy-host/src/remote.rs#L106-L115) · [Worker clock](../../../../crates/tickwire-strategy-sdk/src/worker.rs#L200-L205) · [System source](../../../../crates/tickwire-clock-sys/src/lib.rs#L98-L113)
2. `maintain` samples `t0` and flushes the approved ARM. Pause the host before it calls `try_recv`. The child reads the ARM, samples `t1`, validates the request, creates an ARMED receipt bearing `t1`, stores its object and queues the authenticated reply. Its next loop sends that reply. The Linux report socket receives complete packets and reads the available queue at each `recvmsg`. It has no snapshot at `t0`. The host can resume at `t2` and read the legitimate packet. [Host poll](../../../../crates/tickwire-strategy-host/src/remote.rs#L307-L319) · [Worker request and receipt](../../../../crates/tickwire-strategy-sdk/src/worker.rs#L946-L1018) · [Worker send](../../../../crates/tickwire-strategy-sdk/src/worker.rs#L753-L758) · [Socket read](../../../../crates/tickwire-control-sys/src/linux.rs#L670-L700)
3. `ReadyProof::poll_with` consumes the packet and passes its body to `MarketTransition::observe`. The host verifies the request, authenticated object and receipt using the original `t0`. `Approval::validate_receipt` rejects the true relation `t1 > t0` as `Identity`. When `Strategy::next` sees that error, it calls `fail`, attempts to stop the strategy grant, quiesces its intake, terminates the owned child and records the failure. Future calls skip this instance. An empty read would retry next poll, but the witness has already delivered the packet. [Dispatcher](../../../../crates/tickwire-strategy-host/src/readiness.rs#L76-L91) · [Receipt verification](../../../../crates/tickwire-strategy-host/src/market_transition.rs#L193-L220) · [Timestamp rule](../../../../crates/tickwire-market-source/src/transition.rs#L201-L222) · [Failure handling](../../../../crates/tickwire-strategy-host/src/remote.rs#L293-L305) · [Call site](../../../../crates/tickwire-strategy-host/src/remote.rs#L355-L369) · [Child termination](../../../../crates/tickwire-supervisor/src/lib.rs#L326-L341)

The expansion specification requires current Armed receipts from every approved consumer. Its stop conditions include genuine expiry, broken transport and a failed registration. This schedule has an active session, correct peer and operation, valid approval, fresh resource and time remaining. Revalidating with a fresh same-domain timestamp after receipt would preserve expiry and future-time checks. Tickwire already specifies this sequencing for a JOIN welcome. [Expansion contract](../../../../specs/implementation/market-expansion.md#quiesce-and-cut-over) · [JOIN ordering](../../../../specs/implementation/join.md)

The seven-state TLC trace reaches the failure through an ARM, a host poll, one clock tick, an Armed receipt and its delivery. The native dispatcher test exercised the production report socket, authenticated object lookup and receipt validation. With the poll-start time at 1,500,000,000 ns it rejected a worker receipt stamped one nanosecond later. Supplying 1,500,000,001 ns for validation accepted that receipt.
