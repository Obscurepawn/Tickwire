# L0 输入

核对源码 `crates/tickwire-binance-private/src/{lib,request,client,session}.rs`，v2 修复后的41项私有流和12项时钟组合原生测试、两包Clippy通过，原始检查归 local-deadline 验证目录。历史Linux结果对应修复前源码。模型输入为实际单 owner、一个待确认请求、一个账户和固定认证模式。

使用允许断连、回复丢失/延迟、错误回复和提前事件的故障模式。代码仍负责失败关闭和重新建立连接；上层提供受信账户/API key 绑定、连接代次起点及 mandatory Clock adapter。

时间采用离散毫秒输入：`source_ns = model_ms × 1_000_000`。固定请求/签名窗口5,000 ms、key有效期3,600,000 ms、续期间隔1,800,000 ms、初始退避100 ms，均对应默认配置。量化测试输入只取创建时刻、续期时刻、截止时刻和同步许可后跨截止时刻，不声称覆盖1 ns边界。所有配置的代次/请求数是外部执行长度上限，不是源码计数器最大值；实际u64耗尽以Rust边界测试为证。

v2 单独保留预算回调前的 second 和回调结束后的末次 MonoTime。实际回归使用1秒请求截止、5秒签名窗口及10秒校准有效期；第二次预算回调把 Mono 推进到2秒而 Instant 未到传输截止。修前对端收到219字节；修后为0字节/NoBytes。模型仍取默认5秒请求期限，并枚举回调后恰到该期限的毫秒输入。
