# L0 modeling rationale

Visible states correspond to synchronous `&mut PrivateClient` call boundaries, while first-accept gating splits into two internal stages (`Gate` and `Final`): `GateCallbacksReady` records the pre-callback `second` sample, `GateBudgetExpires` advances monotonic time to the deadline during the synchronous budget callback while retaining that earlier `second`, `FinalSampleExpired` rejects on the post-callback final sample, and `FirstAccept` / `GateBlocked` fire only when the final sample remains within deadline without re-entering other owner APIs. Time advances combine with `poll` expiration checks so wall-clock passage never mutates client status outside a `poll` call.

Byte acceptance is abstracted to `{0, 1, 2}` (`NoBytes`, partial, complete), preserving the exact distinctions needed for request correlation while leaving wire framing bytes to transport tests. Request history retains acceptance level, first-accept timestamp, deadline, and outcome so invariants verify that `NoBytes` never becomes sent, confirmation requires full acceptance, and stale replies cannot mutate newer generations. `Clock` adapter interval math is delegated to the `clock` ladder and modeled via its mandatory call contract.

Authentication mode is fixed per configuration (`SpotSigned`, `SpotLogon`, or `UsdM`). When an API reply and `EOF` arrive in the same poll batch, `Receiving` is revoked before returning; buffered events retain their original connection epoch and must drain completely before reconnecting. Event payloads use a two-value witness domain across buffer capacities `1` and `2`.

USD-M `listenKey` lease validity is anchored to the confirmed request start timestamp rather than reply arrival, and renewal replies check both the prior lease and request deadline. Once an explicit remote `DELETE` begins, automatic reconnect is disabled, and an ambiguous post-accept disconnect latches `remote_close_unknown`. Event sink rejection (`SinkFailure`) permanently transitions the client to `Stopped` rather than reconnecting.

In `v2`, ghost witness `lateCallback` latches whenever the signed-operation `DeliveryBudget` callback crosses the local deadline, and `ExpiredCallbackNeverAccepted` verifies zero bytes are ever accepted afterward. Budget-callback deadline crossing is guarded on `Signed` operations because USD-M `listenKey` requests carry no `SignedTime` and skip `DeliveryBudget`.
