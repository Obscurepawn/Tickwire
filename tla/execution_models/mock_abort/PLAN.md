# Mock 中止与顺序恢复验证计划

当前 `MockRuntime` 的无字节拒绝先保存完整中止记录，再释放资金；`MockJournal` 用统一事件流恢复。旧 submission L1/L2 固定了更早源码，继续作为历史证据保存。本阶梯为当前实现单独建立 L0，不覆盖真实 WAL 或其他 runtime。

`&mut MockRuntime` 串行运行公开调用。模型用 `pc` 保存调用内进度，只有 Idle 才启动另一公开调用；进程可以在持久化、回执、发送及应用之间中断。日志、提交计数跨模拟重启保留。恢复先冻结旧 Engine，再在局部 Engine 重放，最后一次性替换。模型不允许两个线程交叉修改 Engine。

L0 的单一关注点是持久事件顺序如何约束释放和恢复：没有持久中止不能释放；已持久中止在恢复后不重新占用；终态释放发生在后续 intent 前时，恢复保留这个顺序，避免把合法历史变成算术溢出。使用两单主配置、两单最大金额边界和三单扩展配置，全部固定单 worker 并统计动作覆盖。

范围固定为零成交、零费用、LocalDurable、固定请求和合法依赖对象；Pending/Ack/Unknown/NoBytes 均保留。完整记录身份不一致、重复中止和费用矛盾由 Rust 回归检查。故障包含 commit 失败、已写入但回执丢失、事实保存失败、持久事实与 live apply 之间重启。完成此 L0 后停止，不扩展交易结果记录全集或生产存储模型。
